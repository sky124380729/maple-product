# Maple Product 产品规格

版本：0.1  
日期：2026-08-19  
状态：一期设计基线

## 1. 产品定位

Maple Product 是一个仅支持 Windows x64 的桌面自动化程序，面向已授权的游戏测试场景。产品分两期：

1. 一期：定点持续攻击。人物不自动寻路，只在当前站位附近进行攻击和受限左右移动。
2. 一期后续增强：定点识别攻击。人物仍不寻路，只在识别到攻击范围内有怪物时触发攻击。
3. 二期：单张地图自动寻路攻击。人物根据 OpenCV + YOLO 的实时观察在地图内移动、找怪和攻击。

一期必须独立可用，不能依赖识别准确率或二期导航能力。

## 2. 三种定点攻击子模式

UI 保留三个选项：

- `持续攻击`：一期可用。程序按随机长按节奏持续攻击，并按受限随机移动规则左右调整。
- `视觉增强持续攻击`：可选增强模式。攻击节奏保持随机；用户在独立原生预览中框选固定平台安全范围和本人名字模板，Host 只有在视觉安全门授权后才发送左右移动。该模式使用独立控制器，不改变 `持续攻击` 的配置、规划、停止或回中行为。
- `识别怪物后攻击`：一期显示但 disabled，明确标注“后续版本开放”。不能发送命令、不能保存为有效可运行配置，也不能静默降级为持续攻击。

三个模式共享窗口自动定位、失焦停止、Broker 输入链路、日志和状态显示。`持续攻击` 与 `视觉增强持续攻击` 共享随机攻击参数，但不共享移动控制器；未来识别怪物模式不共享攻击触发判定。

## 3. Windows 窗口与会话

一期最低支持 Windows 10 22H2 x64，同时支持 Windows 11 x64。其他 Windows 版本不作为一期发布和验收目标。

用户不选择或配置游戏安装路径。点击“开始”时，Host 枚举可见顶层窗口，只接受窗口标题精确为 `冒险岛怀旧服` 且窗口类精确为 `UnityWndClass` 的客户端。唯一候选自动绑定；找不到候选时提示先启动客户端。游戏自身限制单实例；若系统仍异常返回多个候选，Host 必须停止启动并报告诊断错误，不发送任何输入。不得按模糊进程名、安装目录或最近活动窗口猜测目标。

用户点击“开始”后：

```text
弹出当前人物朝向选择（← / →）
-> 用户确认本次会话初始朝向
自动定位游戏窗口
-> 绑定 HWND/PID/进程路径/进程启动时间
-> 请求将游戏窗口切换到前台
-> 校验窗口在前台且未最小化
-> 启动或连接 Input Broker
-> UAC/Broker 握手完成后再次切换并校验游戏窗口前台状态
-> 建立自动攻击会话
```

关闭朝向选择框、找不到窗口、候选不唯一、无法将游戏窗口切换到前台、身份校验失败或 Broker 不可用时，不发送任何输入。朝向只属于本次启动意图，不保存进配置；每次点击“开始”都必须重新确认。

游戏窗口失去焦点时：

- 立即停止当前自动攻击会话并释放全部按键；
- 更新 UI 状态和本地日志；
- 不弹系统通知，因为失焦通常是用户主动切换窗口；
- 不自动恢复；用户下一次点击开始时重新定位窗口并建立新会话。

自动攻击会话停止后，用户可以手动移动人物。下一次会话启动时，以手动移动后的新位置作为新的相对起点。

## 4. 持续攻击节奏

每轮严格执行：

```text
抽样攻击时长
-> 攻击 key-down
-> 持续按住至截止时间
-> 攻击 key-up
-> 攻击释放缓冲（固定 100ms）
-> 第一方向移动完成
-> 第一方向释放结算缓冲（固定 100ms）
-> 随机无按键间隔
-> 相反方向移动完成
-> 稳定等待
-> 可选休息
-> 重新抽样并进入下一轮
```

攻击时长默认分布：

| 权重 | 范围 |
|---:|---:|
| 97% | 1–10 秒 |
| 1% | 10–20 秒 |
| 1% | 20–40 秒 |
| 1% | 40–60 秒 |

四段边界和权重均可配置，但一期产品硬上限为 `60,000ms`，任何 UI、配置、Host 或 Broker 值都不得超过该上限。抽样按 `1ms` 粒度执行，例如 `27,438ms`，不能量化为整秒或固定档位。

一轮攻击只能有一次攻击 `key-down` 和一次对应 `key-up`。中途停止、失焦、Broker 异常、窗口身份变化或安全门失败时立即 `key-up` 并最终 `ReleaseAll`。

攻击 `key-up` 成功后必须等待固定 `100ms` 的无按键释放缓冲，避免游戏仍在处理攻击收尾帧时吞掉紧随其后的短方向键。缓冲完成前不得发送第一方向，也不得进入下一轮攻击。

普通持续攻击的第一方向 `key-up` 成功后也必须先等待固定 `100ms` 的方向释放结算缓冲，再独立抽取并等待配置的两段随机无键间隔，之后才能发送第二方向。`MoveGap` 权威阶段时长等于 `100ms + sampledMoveGapMs`；固定缓冲只隔离游戏输入结算帧，不能替代、裁剪或固定随机间隔。该规则不改变两段随机按压、固定方向顺序、最终朝向或视觉增强模式的独立移动控制器。

`ReleaseAll` 和关闭连接属于无条件安全回收命令：即使窗口已经失焦、最小化、消失或身份变化，Broker 也必须尝试释放已记录的全部活动键；这些命令不能被目标窗口安全门拒绝。

## 5. 会话级受限随机移动

移动不是每轮回到原点，而是一个持续整个自动攻击会话的随机游走：

- 会话启动时将人物当时位置视为相对零点，累计程序位移清零。
- 会话运行期间不因攻击轮结束、移动轮结束或休息而清零。
- 一轮必须使用两个相反方向。第一段固定为本次会话初始朝向的反方向，第二段固定为初始朝向，使人物每轮结束后恢复到启动时指定朝向。
- 两段按压时长分别随机，不复制、不固定相等、不强制抵消到原点；接近边界时允许按本节规则改变候选范围和回中概率，但不能退化为固定配对脚本。
- 累计位移始终不能超过配置的左右最大阈值。
- 只有自动攻击真正停止后，下一次启动才重新设零点和清零累计位移。

一期默认移动参数：

| 参数 | 默认值 | 说明 |
|---|---:|---|
| 每侧最大累计偏移 | 80ms | 会话内相对起点的左/右安全阈值，可配置 |
| 单段方向键按压 | 30–50ms | 1ms 粒度；使用已验证的实机参数 |
| 两段之间随机无键间隔 | 30–120ms | 1ms 粒度；在第一方向固定 100ms 释放结算缓冲后独立抽取 |
| 第二段后的稳定等待 | 80–150ms | 未完成前不得重新攻击 |

累计位移必须使用 Broker 测得的方向键成功物理 `keybd_event` Down 至成功物理 Up 的实际持续时间计算，不能使用 Host 请求的计划时长猜测。第一方向释放、返回真实时长并更新累计偏移后，才能计算第二方向的安全预算。真实时长缺失、不在 `1–5,000ms` 内或使累计偏移越界时，当前会话必须停止并 `ReleaseAll`。

每次准备按键前，根据当前会话累计位移计算该方向剩余安全空间，并预留固定 `20ms` 的释放抖动余量后再抽样。第一段候选必须预演从“计划保持时长”到“计划保持时长 + 20ms”的全部可能实际时长，并保证每个落点都仍存在合法第二段；不能只按第一段计划时长或单个端点预演后续预算。正常双段第一方向空间不足时，不终止攻击会话，也不交换固定方向顺序；Host 改为从仍满足硬边界与 `20ms` 余量的初始朝向候选中随机执行一次安全恢复。没有安全恢复候选时，本轮冻结移动并继续攻击。

随机移动使用分区回中策略。绝对偏移不超过阈值 `40%` 时保持无偏随机；处于 `40%–70%` 时，每轮以 `75%` 概率选择随机回中意图、以 `25%` 概率继续安全范围内的普通随机；超过 `70%` 时必须选择随机回中意图。回中轮结束后的绝对偏移变小或相等时清除回中债务；因真实释放抖动而变大时不再以 `MOVEMENT_RETURN_UNSATISFIED` 终止会话，而是记录回中债务并强制下一轮继续选择回中意图，直到后续回中轮不再恶化。两段时长仍从所有满足方向顺序、真实剩余预算和硬边界的合法值中分别抽样；移动结果允许保留随机净位移，不能固定“左 40ms、右 40ms”或每轮归零。

一期由用户在启动弹窗中提供朝向。Host 必须通过可替换的朝向来源接口解析启动意图，控制器和移动规划器只依赖解析后的 `Left/Right`，不得依赖 React 或视觉实现。未来可新增一次性视觉朝向来源；视觉检测不确定时必须拒绝启动或回退到明确的人工确认流程，不能盲猜。

## 6. 前端倒计时与状态

Host/运行时发布权威节奏状态，至少包含：会话 ID、周期 ID、阶段、抽样总时长、阶段开始单调时间、阶段截止单调时间、剩余毫秒和提前结束原因。

持续攻击页面必须显示：

- 本轮抽中的攻击总时长；
- 毫秒级剩余值，例如 `剩余 27.438 秒`；
- 当前阶段和下一步阶段；
- Host 当前计算的会话累计偏移，负数表示左、正数表示右；
- 重新抽样后立即从新总时长重新倒计时。

前端只展示，不根据倒计时或偏移量发送动作。累计偏移在每段方向键释放并完成真实时长记账后更新；显示格式为 `-23 ms（左）`、`+17 ms（右）` 或 `0 ms（中心）`。识别关闭时仍必须显示。停止后保留本次会话最终偏移供诊断，下一次开始时清零；释放攻击、停止、失焦和异常后清除旧倒计时。

视觉增强模式另外发布本人人物外观匹配分数、安全状态和相对平台安全区中心的像素偏移；像素偏移同样使用负数表示左、正数表示右。React 只能显示这些结构化字段，不能接收逐帧像素、提交视觉坐标或据此发送输入。`relativeOffsetMs` 在视觉增强模式中继续显示，但只作为时间模型诊断值，不能覆盖视觉安全门。

## 7. UI

主窗口使用 React + Ant Design，保持简单配置形态：

- 客户端自动检测/开始/停止；
- 定点攻击模式选择；
- 攻击键和所有一期调试参数；
- 当前会话、阶段、倒计时、输入状态和错误信息；
- 打开实时预览按钮。

一期先开放全部调试配置，后续可隐藏高级项，但后端能力和配置兼容性保留。非法值不能保存或启动；运行中修改的节奏参数从下一完整周期生效。

方向键计划保持时长不得超过 Broker 的 `5,000ms` 硬上限；`maxLateralMoveMs` 必须至少等于 `moveHoldMinMs + 20ms`，否则没有任何满足最短按压与释放抖动余量的合法移动，配置必须拒绝保存和启动。

一期攻击键使用受控白名单：`Ctrl`、`Shift`、`Space`、`A`、`S`、`D`、`F`、`Z`、`X`、`C`、`V`。默认值为 `Ctrl`。UI、配置校验、Host 协议和 Broker 映射必须使用同一白名单；不得接受任意字符串、任意虚拟键码或运行时扩展键值。

实时预览不是主窗口内嵌区域，而是可选的独立原生窗口。预览与攻击会话独立，用户在未开始攻击时也可以打开；空闲时 Host 自动按精确窗口规则发现唯一客户端，运行中优先复用当前会话绑定的目标。关闭、卡顿或崩溃预览不能阻断持续攻击模式。识别开启时，React 主窗口显示角色名称、等级、职业、HP、MP、EXP、结果新鲜度和置信度；原生预览只显示采集画面、人物/怪物识别框、视觉本人候选、FPS、帧龄和识别故障，不重复显示静态 HUD 数据。

视觉增强模式在原生预览中提供两步框选：黄色框由用户选择平台外层安全范围，纵向可以包含人物和平台图像；绿色框是 Host 按保护带自动缩出的安全核心，不是第二次选择。人物在绿色框内可执行双向随机移动，位于黄色外框与绿色核心之间时只允许向平台内部修正，越过黄色外框时冻结移动。新配置的第二步使用蓝框紧贴选择本人头部和上半身，不包含名字、宠物或大面积武器/技能特效。游戏画面覆盖层只绘制黄色、绿色、蓝色、青色和橙色边框及轻透明填充，不在框内、框边或拖拽框附近绘制用途、步骤、匹配分数等任何文字；颜色含义、当前框选步骤、校准进度、保存结果和实时匹配分数统一显示在画面外的工具栏或底部状态栏。配置存在时，预览在空闲和视觉增强运行期间持续执行同一人物外观匹配：可信结果用青色框显示，尚未达到连续可信门槛或当前失信但仍有候选时用橙色框显示，不得把配置源蓝框冒充实时识别结果；候选框必须与同一序列的捕获帧成对绘制，不能把新坐标覆盖到旧画面。框选后 Host 先等待 `3s` 供用户把焦点切回游戏，再在约 `6s` 内均匀采集左右朝向和施法姿态；采集在原框各轴 `12px` 邻域内局部对齐，允许新姿态以 `0.60` 校准分数入库，保存冻结首帧加最多 7 个互不重复的固定外观模板。运行时同时使用真实采集模板及水平镜像兼容朝向变化，模板不得在运行中在线替换或追加。主界面和原生预览工具栏都提供清空视觉配置命令；攻击或寻路的启动准备及运行期间拒绝重新配置和清空，清空成功后立即删除持久化配置、人物观察会话和全部视觉框，必须重新框选才能启动视觉增强模式。

人物外观首次锁定先在保存位置水平和垂直各 `12px` 邻域内快速搜索，局部证据不足时立即扫描用户黄色平台外框覆盖的完整区域；首次候选无论位于蓝框原位或黄色框其他位置，都要求最佳分数至少 `0.70`、最佳与空间分离次佳差值至少 `0.06` 且连续 3 个新帧稳定，不要求人物回到保存蓝框的原始位置。已有可信轨迹同样采用两级搜索：先在上一可信锚点各轴 `12px` 邻域内用 `0.68` 跟踪阈值和 `0.04` 局部次峰差值快速匹配，局部证据不足时扫描完整黄色框。黄色框内远离锚点的候选必须重新满足 `0.70`、`0.06` 和连续 3 个新帧稳定，才允许迁移锚点及恢复移动；`0.68` 只用于原锚点附近的既有轨迹维持和局部恢复。黄色外框是第二级人物重获的唯一识别区域边界，绿色安全核心、保护带宽度和中心回正带不得裁剪或改变人物搜索；绿色核心只参与可信人物位置后的移动方向授权。跟踪锚点不得由低于重新定位门槛或尚未连续稳定的远距离候选推进，不能让连续低分背景把锚点逐帧带离本人。外观分数除抗局部遮挡的颜色和边缘分量外，必须包含模板与候选的归一化亮度结构相关性；候选采样亮度范围不足 `16` 的纯色或低纹理区域必须作为无效证据返回低于最低跟踪阈值 `0.68`，不能由抗遮挡分量抬高。同一人物外观框中心相距不足半个模板宽且半个模板高的相邻匹配峰属于同一目标，不得作为空间次峰制造歧义；只有空间上分离的候选才参与次峰判断。黄色框外的相似人物即使原始分数更高也不能参与候选或替换本人；局部歧义、缺失、重复帧、未确认的远距离跳变、低于对应阈值或捕获故障立即撤销移动授权。旧版名字配置继续按原名字匹配规则读取，但重新配置默认生成 schema 2 人物外观配置。配置绑定客户区捕获宽高，尺寸或 DPI 投影变化时拒绝启动并要求重新框选。

兼容已保存的窄平台框：若黄色框纵向没有覆盖人物模板中心，第二级搜索仍覆盖黄色框完整横向范围，纵向沿已保存或最后可信人物高度保留 `12px` 邻域；不得因旧平台框只贴台阶而把人物模板排除。新框选仍建议让黄色框纵向同时包含人物和平台。

视觉安全状态为 `Acquiring`、`TrustedSafe`、`TrustedGuardLeft`、`TrustedGuardRight`、`UntrustedFrozen`、`OutsideFrozen` 和 `FallbackContinuous`。中心带定义为 `abs(visualOffsetPx) <= guardWidthPx`：中心带内继续执行随机双向动作；可信位置超出中心带但仍在外框内时执行随机时长的向内修正，不用等长向外第二段抵消。若该向内方向已经等于会话初始朝向，本次修正结束后可进入下一轮攻击；若向内方向与初始朝向相反，控制器必须进入 `FacingRestorePending`，在同一攻击间隔内继续用独立随机时长向内修正，直到重新进入中心带并取得初始朝向的安全授权，再以一次随机时长的初始朝向动作结束。视觉仍可信时，下一轮 Attack.Down 不得早于 `VISUAL_FACING_RESTORED`。进入单侧保护带后同样只允许随机长度的向内动作；超出外层框时冻结全部左右移动。移动授权必须把同一时刻的可信观察、具体左右方向和撤销令牌作为原子快照返回；从安全区进入左保护带必须立即撤销旧的向左授权，进入右保护带必须立即撤销旧的向右授权，不能用仍然有效的另一方向令牌执行危险方向。人物身份连续不可信不足 `15s` 时冻结移动但继续攻击；达到 `15s` 后，同一个视觉会话改用普通持续攻击的 `StationaryMovementPlanner`，按真实累计 `relativeOffsetMs` 的方向、`maxLateralMoveMs` 和初始朝向执行随机双向移动及随机回中，不以视觉 `px/ms` 校准作为启动条件；若视觉阶段的时间模型已超出毫秒边界，回退规划器只把初始值压到同符号的边界值，不能因此停止攻击。回退双向动作的 `MoveGap` 与普通持续攻击一致，严格等于固定 `100ms` 方向释放结算缓冲加配置范围内独立随机间隔。回退方向周期从首段开始到稳定等待结束保持人物锚点跟踪窗口开启；人物外观重新连续 3 个新帧可信后，在下一完整移动周期退出普通持续攻击回退，并按最新真实像素位置切回视觉平台保护，不得在左右动作对中间切换。身份可信但越过平台外框不触发回退。中心带内第一段反向方向键 Down/Up 成功而第二段未执行时同样进入 `FacingRestorePending`；连续失信达到 `15s` 后必须结束该等待并继续下一轮随机攻击与普通随机移动，不能无限暂停攻击。观察陈旧或捕获/预览故障同样允许在 `15s` 后进入普通持续攻击回退；配置 schema/视口结构错误仍拒绝视觉会话启动。失焦、窗口身份、Broker 和按键释放故障仍立即停止并 `ReleaseAll`。

已保存且通过 schema 与当前视口校验的视觉配置在重新开始时直接复用。启动预检暂时低于锁定阈值、歧义、遮挡或局部未找到时仍启动攻击会话，左右移动冻结并继续逐帧锁定；不得删除配置或要求重新框选。Broker/UAC 准备完成后、首次输入前复查最新观察，新鲜临时失信仍允许冻结启动，陈旧或 fatal 状态不得发送攻击。只有配置缺失、schema/像素非法或视口尺寸变化才要求重新配置。

## 8. 输入与异常通知

生产输入链路固定为：普通权限 Host -> 管理员 Input Broker -> 命名管道 -> `keybd_event`。Broker 启动、身份校验、心跳、watchdog 和释放策略沿用已验证的 Windows integrated 路径，但在新仓库中重新实现和测试。

Broker 必须使用 Windows integrated 路径已验证的虚拟键与 Set-1 扫描码组合：`Ctrl=0x11/0x1D`、`Shift=0x10/0x2A`、`Space=0x20/0x39`，白名单字母使用对应 Set-1 扫描码；左右方向键分别使用 `0x25/0x4B`、`0x27/0x4D` 并设置 extended flag。不得把普通键的扫描码统一发送为 `0`。

定点攻击的左右移动正常路径沿用 `7875384` 的释放方式：Host 完成随机抽样保持后主动发送 `KeyUp`。为了避免 Host 调度停顿把短移动扩大到数百毫秒，Broker 必须把定点方向键注册到高精度移动释放调度器，并在“计划保持时长 + `20ms` 固定释放余量”处只释放当前方向键；这属于 `HostKeyUp` 模式的精确 watchdog 兜底，不把定点请求改成寻路的精确计划截止语义。普通 250ms watchdog 不得抢先释放定点方向键或连带释放攻击键。Broker 必须为显式 `KeyUp` 返回方向键实际按压时长与相对计划时长的释放迟到量；即使精确兜底在显式 `KeyUp` 到达前先完成了物理释放，也必须保留本次计时并由随后的幂等 `KeyUp` 返回，不能返回缺失计时的成功响应或重复物理释放。Host 恢复后继续本轮并只按实际时长更新累计偏移。定点与自动寻路请求必须在 Broker 协议中明确区分；自动寻路的 `BrokerDeadline` 仍按计划时长截止，不得因定点兜底增加 `20ms`。

自动停止规则：

- 失焦：静默停止；
- 用户点击停止：静默停止；
- Broker 断开、心跳超时、按键释放失败、窗口消失、身份变化、运行时未处理异常：停止、ReleaseAll、写日志并发送一次 Windows 系统通知；
- 程序退出或崩溃：Broker watchdog 必须释放按键；下次启动展示上次异常终止记录。

一期不注册全局快捷键。

## 9. 明确非目标

- 一期不实现自动寻路、跨平台运行或识别触发攻击。
- 视觉增强模式不自动识别平台边缘、不补偿大范围相机滚动、不训练本人分类模型，也不启用怪物识别攻击。
- 不使用 Virtual HID、SendInput、PostMessage 或 React 原始按键。
- 不把持续攻击默认行为偷偷用于 disabled 的识别模式。
- 不把旧仓库的实验资产、探针、虚拟 HID 契约、三栏实时工作台或冲突规格整体迁入。
