# 一期定点攻击验收清单

## A. 纯逻辑与契约

- [ ] 攻击时长按四段权重抽样：97/1/1/1；每段边界正确；1ms 粒度；任何层都拒绝超过 60,000ms 的值。
- [x] 每次点击开始先弹出 `←/→` 朝向确认框；关闭弹窗不启动、不连接 Broker，选择不写入持久化配置。
- [x] 初始朝左时每轮严格按 `右 -> 左`，初始朝右时每轮严格按 `左 -> 右`，第二段结束后恢复到用户指定朝向。
- [ ] 两段移动时长和间隔分别抽样，不复制、不固定相等、不量化为 50/100ms 档位；边界与回中意图只缩小合法候选集合。
- [ ] 会话启动清零累计位移；每轮攻击/移动/休息不清零；停止后下次启动重新清零。
- [ ] 任何抽样都不会让累计偏移超过配置的每侧阈值，默认 80ms。
- [ ] 累计偏移只按 Broker 返回的真实方向键按压时长逐段更新；第一段真实时长提交后才计算第二段，计划 40ms、真实 46ms 时按 46ms 记账。
- [ ] 每段抽样预留 `20ms` 释放抖动余量；第一段对“计划保持..计划保持 + 20ms”的全部实际落点验证仍有合法第二段，不能因不超过余量的释放延迟在第一段后误报 `MOVEMENT_BUDGET_EXHAUSTED`；真实时长非法或真实 offset 越界时仍安全停止并 ReleaseAll。
- [ ] 回中分区为 `0%–40%` 无偏随机、`>40%–70%` 以 `75%` 概率回中、`>70%` 必须回中；回中后的非零落点和两段时长仍有随机变化，不固定相等、不固定差值、不强制归零。
- [ ] 回中轮末绝对偏移小于或等于开始值时清除回中债务；大于开始值时不停止，下一轮强制继续回中；运行中缩小阈值至当前真实 offset 之外时仍以 `MOVEMENT_OFFSET_EXCEEDED` 停止。
- [ ] 指定的第一方向预算不足时不停止、不交换两段顺序；随机执行安全的初始朝向恢复动作后继续攻击，没有安全恢复候选时冻结本轮移动并继续攻击。
- [ ] 配置 schema 拒绝非法范围、权重不为 100 和 disabled 识别模式启动。
- [ ] 配置拒绝 `moveHoldMaxMs > 5,000`，并拒绝 `maxLateralMoveMs < moveHoldMinMs + 20ms`；UI 与 Host 使用相同规则。
- [ ] 配置不要求或校验游戏 exe 路径；UI 不显示路径选择器；UI、Host、Broker 使用相同攻击键白名单并拒绝白名单外攻击键。
- [x] Host 通过可替换朝向来源解析启动意图；人工来源可独立测试，未来视觉来源无需修改控制器或移动规划器。

## B. 状态机与按键顺序

- [ ] 每轮攻击严格为一次 Attack.Down、一次 Attack.Up。
- [ ] Attack.Up 后完成固定 100ms 无按键释放缓冲，缓冲结束前不发送第一方向或下一轮 Attack.Down。
- [ ] 第一方向 Down/保持/Up 完成后进入 `MoveGap`；该阶段严格等于固定 `100ms` 方向释放结算缓冲加一次配置范围内独立随机间隔。
- [ ] 固定缓冲和随机间隔都完成后才进入第二方向；随机间隔不得被固定、裁剪或省略，普通持续攻击的最终方向顺序仍由初始朝向决定。
- [ ] 第二方向 Down/保持/Up 任一失败，直接停止并 ReleaseAll，不进入下一轮攻击。
- [ ] 第二方向 Up 成功后必须完成稳定等待，之后才重新抽样攻击。
- [ ] 移动期间不允许攻击键活动；所有异常路径释放全部活动键。
- [ ] 定点左右键正常由 Host 按计划保持后主动 KeyUp；协议测试证明 `HostKeyUp` 请求在计划时长 `+20ms` 注册精确单键兜底、普通 watchdog 不抢先处理该方向键，`BrokerDeadline` 寻路请求仍在原计划时长截止。
- [ ] 定点方向键的显式 KeyUp 返回 actualHoldMs/releaseLatenessMs；watchdog 抢先释放后，幂等 KeyUp 仍返回同一真实计时且不重复物理 Up；请求时长、真实时长、迟到量和提交后的 offset 写入结构化日志。

## C. UI 与倒计时

- [ ] UI 显示持续攻击、独立可用的视觉增强持续攻击和 disabled 的识别攻击选项；视觉模式实现不得改变原持续攻击控制器的既有按键序列、随机边界和停止规则。
- [ ] 未启动攻击时也可打开独立实时预览；空闲时自动发现唯一客户端，运行中复用绑定目标。
- [ ] 识别开启后，React 主窗口以结构化快照显示角色名称、等级、职业、HP、MP、EXP、置信度和新鲜度；不通过 bridge 传输逐帧像素。
- [ ] 原生预览只显示真实人物/怪物框、FPS、帧龄和识别故障；模型无结果时显示 0/未识别，不绘制假框。
- [ ] 原生预览用黄色平台外边界、绿色双向随机移动核心和蓝色人物模板框显示配置，用青色可信本人框或橙色候选框显示实时匹配；画面覆盖层及拖拽框只含边框和轻透明填充，不绘制任何用途、步骤或分数文字，相关说明与实时分数只出现在画面外状态栏；候选不得取得移动授权。
- [ ] 主窗口和原生预览都可清空视觉配置；攻击或寻路的启动准备及运行中拒绝重新配置和清空，空闲时清除成功会删除磁盘配置、人物观察会话和全部视觉覆盖框；丢帧合并时实时人物框与显示位图来自同一帧序列。
- [ ] 每次新攻击抽样后显示新的总时长、cycleId 和毫秒级剩余值。
- [ ] 角色信息区域显示 Host 计算偏移：负数为左、正数为右、零为中心；识别关闭时仍显示，每段方向键释放后更新。
- [ ] 停止后保留本次会话最终偏移，下一次点击开始时重置为 0；前端只展示偏移，不据此发送输入。
- [ ] 倒计时依据 phase deadline，不使用固定递减计数器。
- [ ] 停止、失焦、异常后旧 session 倒计时清除。
- [ ] 所有调试参数可编辑、校验、保存和恢复安全默认值。

## D. Windows 输入

- [ ] Host 自动定位窗口、请求切换到前台，并绑定 HWND/PID/路径/启动时间；切换失败时不发送输入。
- [ ] UAC/Broker 握手完成后 Host 再次激活并校验同一窗口；失败时关闭 Broker 且不进入攻击控制器。
- [x] Host 仅按精确窗口标题 `冒险岛怀旧服` 与窗口类 `UnityWndClass` 自动发现唯一客户端，不要求用户选择 exe；零候选或异常多候选时不发送输入。
- [ ] Broker 以管理员权限启动，命名管道只允许当前用户主程序连接。
- [ ] Broker 使用 Windows GUI 子系统且不显示控制台窗口；启动、运行和退出不会抢占游戏前台。
- [ ] 每次动作检查前台窗口、目标身份、心跳和动作租约。
- [ ] 失焦静默停止；Broker/释放/窗口身份/运行时异常发送一次 Windows 系统通知。
- [ ] Broker watchdog 在 Host 失联或心跳超时后释放全部按键。
- [ ] 动作租约到期只释放活动键而不解除目标；随后幂等 `KeyUp` 成功并带回真实计时，控制器可以继续左右移动而不触发 `MOVEMENT_TIMING_INVALID`。
- [ ] `ReleaseAll/Close` 在失焦、最小化或身份变化时仍执行安全释放，不被目标窗口安全门拒绝。
- [ ] Broker 映射测试证明 `Ctrl` 使用 `VK_CONTROL + scan 0x1D`，白名单字母使用 Set-1 扫描码，左右方向键使用扫描码和 extended flag；真实游戏输入不得使用零扫描码的攻击键。
- [ ] Windows 实机记录 Broker 事件、真实 keybd_event 结果和游戏画面响应。

## E. 构建与发布

- [ ] macOS 可执行平台无关测试和 React 测试。
- [ ] Windows x64 Host/Broker 交叉编译成功。
- [ ] Windows 10 22H2 x64 和至少一个受支持的 Windows 11 x64 环境完成启动门验证；更低版本明确拒绝运行自动攻击。
- [ ] Windows 实机完成 Broker、窗口、失焦、异常通知和长时间运行验证。
- [ ] 首次交付为完整发布目录或 ZIP，不要求一期安装程序。

## F. 视觉增强持续攻击

- [ ] 原生预览完成平台与人物外观两步框选：黄色为用户选择的平台外框且允许包含人物，绿色为 Host 自动计算的安全核心，蓝色为用户选择的本人头部和上半身；人物框不含名字、宠物和大面积特效，并按 1366 宽参考视口校验 `24x32` 至 `112x144`、纹理、视口和像素长度。
- [ ] 绿色安全核心不是用户的第二次选择：核心内允许双向随机移动，黄色外框与绿色核心之间只允许向平台内部修正，黄色外框之外冻结移动；颜色含义通过画面外紧凑图例解释。
- [ ] 新配置框选后先等待 `3s` 供用户切回游戏，再在约 `6s` 内均匀采集 7 张实时帧；采集在原框各轴 `12px` 邻域以最低 `0.60` 分数局部对齐，固定模板库为冻结首帧加最多 7 个新模板，相似度达到 `0.97` 的重复模板丢弃。运行时使用固定模板及水平镜像，不在线更新；旧 schema 1 名字配置仍可读取，重新配置生成 schema 2 `CharacterAppearance`。
- [ ] 人物外观首次锁定先搜索保存位置各轴 `12px` 邻域，局部证据不足时立即扫描整个黄色平台外框；首次候选无论位于蓝框原位或黄色框其他位置，都要求至少 `0.70`、空间次峰差值至少 `0.06`、连续 3 个新帧，不要求重新框选。已有可信轨迹先在当前锚点各轴 `12px` 邻域用 `0.68` 和局部次峰差值 `0.04` 快速跟踪，局部证据不足时同样扫描整个黄色平台外框。黄色框内远离锚点的恢复候选必须重新达到 `0.70`、`0.06` 且连续 3 帧才迁移锚点并恢复信任；`0.68` 不能用于首次锁定或远距离恢复，`0.67` 仍立即撤销局部信任。绿色核心、保护带和中心回正带不裁剪人物搜索；同一人物框中心相距不足半个模板宽且半个模板高的相邻峰必须合并，不能被误判成第二个人物；黄色框内空间分离的真实第二候选仍立即冻结移动，框外人物不参与候选。连续低分或未稳定的远距离候选不得把锚点累计带离本人。
- [ ] 人物外观候选同时具备颜色/边缘抗遮挡分数和归一化亮度结构证据；候选采样亮度范围不足 `16` 的纯色或低纹理背景即使稳健分量偏高也必须低于最低跟踪阈值 `0.68`，真实人物模板及约 20% 局部遮挡仍可通过。
- [ ] 旧黄色平台框仅贴台阶、纵向未覆盖人物模板中心时，第二级搜索仍覆盖黄色框完整横向范围并沿保存人物高度保留垂直 `12px` 邻域，不要求清空或重画旧配置。
- [ ] 黄色全域匹配使用按视口缩放且限制在 `2..8px` 的粗搜网格，并逐像素精搜最佳与空间次佳两个峰；8 张固定动作模板仍能在黄色框另一侧完成连续 3 帧获取，两个同分空间候选仍判定歧义，不能用只精搜最佳峰换取性能。
- [ ] 宠物或特效遮挡人物模板约 20% 时，稳健匹配仍能保留唯一局部本人候选；证据不足、两个局部相似候选、重复帧或跳变立即撤销移动授权。
- [ ] 画面内存在多个其他玩家时，不得使用中心最近通用人物框，也不得进行全帧人物搜索；局部范围外即使存在更高分相同外观也不得替换本人。人物局部搜索矩形只跟随保存位置或已授权动作后的可信锚点，人物中心越过绿色安全核心或中心回正带时仍继续搜索，不得用黄色/绿色平台区域裁剪搜索。
- [ ] 平台安全门区分内部安全区、左右保护带、外层越界和不可信状态；保护带在会话中可以扩大但不能缩小。
- [ ] 移动反馈扩大保护带时立即用最新可信位置重新分类并撤销新变危险的方向授权，不等待下一捕获帧；保护带耗尽安全区时冻结两侧移动。
- [ ] `abs(visualOffsetPx) <= guardWidthPx` 的中心带内保持随机双向动作；可信位置超出中心带但仍在外框内时只执行随机时长的向内修正，不追加等长向外抵消段；左保护带只允许随机向右、右保护带只允许随机向左；不可信或越过外框时不发送左右键。
- [ ] 单向回正方向若与初始朝向相反，当前攻击间隔进入 `FacingRestorePending`：每段按配置独立随机抽样并继续安全向内，回到中心带后以一次随机初始朝向动作结束；视觉持续可信期间，下一轮 Attack.Down 必须晚于 `VISUAL_FACING_RESTORED`，不能出现连续一轮或多轮反向攻击。
- [ ] 每段移动释放并稳定后必须等待序列更新的可信帧，动作期间、释放前或重复的旧帧不能触发下一段移动。
- [ ] `Safe` 观察与移动授权在方向键按下前发生相邻帧竞态时，同一段在 `750ms` 上限内等待新的连续可信帧并重新安全判断，不得静默漏掉一侧；超时、保护带拒绝或外层越界仍不发送移动键。
- [ ] 移动授权以同一处理锁内的“可信观察 + 具体左右方向 + 撤销令牌”原子快照提供；进入左保护带立即撤销旧向左令牌但保留向右令牌，进入右保护带反之，外层越界或不可信撤销两侧，控制器不存在旧观察配通用令牌的竞态。
- [ ] 授权重试、移动反馈和朝向恢复的视觉条件等待均拆成不超过 `100ms` 的片段；片段边界检查窗口安全门，等待中失焦时在发送下一方向键前停止并 `ReleaseAll`。
- [ ] 中心带内第一段反向方向键已执行但第二段未执行，或中心带外单向修正使人物背离初始朝向时进入 `FacingRestorePending`，UI/日志状态不被普通观察帧提前覆盖；恢复成功显式发布 `VISUAL_FACING_RESTORED`。恢复等待使用 `750ms` 分段条件，连续视觉不可用以 `15s` 为总上限；达到上限后必须结束等待，并在下一轮继续随机攻击和普通持续攻击移动，不得因视觉校准不足无限阻塞。
- [ ] 可信移动按左右方向分别用视觉 X 变化和 Broker `actualHoldMs` 校准 `px/ms`；反向、少于 `2px`、低于 `0.05` 或高于 `2.50 px/ms` 的样本丢弃，每侧只保留最近 8 个并取中位数，左右各少于 2 个样本时不得盲走。
- [ ] 人物外观连续失信不足 `15s` 时冻结左右移动并继续随机攻击；达到 `15s` 后，同一视觉控制器无条件切换到普通 `StationaryMovementPlanner`，按真实累计 `relativeOffsetMs` 的方向、`maxLateralMoveMs`、初始朝向和随机回中规则继续随机双向移动，不要求 `px/ms` 校准；时间模型超出边界时压到同符号边界继续，不能停止攻击。双向回退的 `MoveGap` 等于固定 `100ms` 加配置范围内独立随机间隔，回退动作周期保持人物锚点跟踪窗口开启。观察陈旧或捕获/预览不可用同样累计 `15s` 后进入普通回退；重新连续 3 帧可信后在下一完整移动周期切回视觉保护。身份可信但平台外框越界不回退；schema/视口结构错误拒绝启动；失焦、窗口身份和 Broker 故障仍立即停止并释放全部输入。
- [ ] 已保存且 schema/像素/视口校验有效的视觉配置在重新开始时直接复用；3 秒预检内暂时低分、遮挡、歧义或未找到不得拒绝启动或要求重画，而是启动攻击并冻结移动、继续逐帧重获。Broker/UAC 准备后、首次输入前再次检查最新观察，新鲜临时失信仍允许冻结启动，陈旧或 fatal 状态不发送攻击；仅配置缺失、结构非法或视口变化要求重新配置。
- [ ] 主界面在回退期间显示 `持续攻击回退`，连续观察事件不得把回退状态覆盖成普通不可信；恢复视觉保护后状态自动清除。
- [ ] 主界面只显示结构化配置状态、安全状态、身份类型、匹配分数和带符号 `visualOffsetPx`；React 不接收模板/帧像素，不提交平台坐标、随机数或方向动作。
- [ ] 主界面提供带确认的“清空视觉配置”命令；清空只删除本地视觉档案并把状态改为未配置，不修改普通持续攻击参数，运行期间不能执行。
- [ ] Windows 实机长时间运行覆盖其他玩家进入、名字短时遮挡、左右保护带和技能特效；可信移动期间人物不越过框定平台外层边界，日志与发布包哈希留档。

## 明确不能宣称的结果

macOS 测试或 Windows 交叉编译不能证明 `keybd_event` 对真实游戏有效；必须有 Windows 实机证据。识别攻击和自动寻路在一期验收中保持未启用。
