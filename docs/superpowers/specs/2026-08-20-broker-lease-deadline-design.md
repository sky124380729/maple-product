# Broker 按键租约截止设计

日期：2026-08-20

## 问题

当前 Host 使用 `Task.Delay(holdMs)` 后主动释放按键，Broker 只在 `250ms` watchdog 中检查租约。系统负载升高时，配置为 `25-49ms` 的方向键可能晚于计划上限释放，而移动规划器仍按抽样值累计偏移。窄平台上，逻辑偏移与游戏实际位移会因此失配；同时，仅按净偏移限制会让左、右交替后已消耗的方向预算被错误恢复。

## 决策

Broker 成为物理按键租约截止的唯一所有者。每次成功发送物理 `key-down` 后，Broker 同步登记开始时间、截止时间和 generation，并交给独立高优先级单调截止调度器。调度器不依赖命名管道读取循环、Host、heartbeat 或 `250ms` watchdog。

到达截止时间时，Broker 在进程内直接发送物理 `key-up`。Host 随后发送幂等 `KeyUp` 确认结果：按期自动释放返回 `KEY_LEASE_EXPIRED`；Host 在截止前主动释放返回 `KEY_UP_SENT`；释放晚于截止返回 `KEY_LEASE_DEADLINE_MISSED`；物理释放失败返回 `KEY_LEASE_RELEASE_FAILED`。后两者拒绝请求，使现有控制器进入停止和 `ReleaseAll` 路径。

## 调度器

生产调度器维护活动 action 到 deadline/generation/callback 的映射，并由单一后台线程等待最早截止。线程使用单调毫秒时钟、提前唤醒加短自旋抵达截止点，并设置高线程优先级。新增、取消或替换租约时唤醒线程重新计算最早截止。回调在调度器锁外执行，避免与 Broker 会话锁形成死锁。

测试使用可控的手动调度器，不依赖真实时间。测试必须证明：成功 KeyDown 立即登记截止；触发截止会释放且不解除目标；旧 generation 不能释放新租约；显式 KeyUp/ReleaseAll 会取消任务；晚释放和释放失败会在确认时拒绝 Host。

## 状态与异常

Broker 会话为每个 action 保存活动租约和最近一次自动释放结果。显式 KeyUp 与截止回调都在同一会话锁内串行化。先取得锁的一方完成释放，另一方只能读取幂等结果，不能重复发送物理 KeyUp。

`250ms` watchdog 继续负责 heartbeat 超时、窗口身份和失焦兜底，但不再作为动作租约的正常执行路径。任何安全回收都会取消所有截止任务并清除已完成结果。

## 边界

该修复保证程序不再把 Host 的软延迟当作物理按键上限，并要求移动规划器分别限制左右累计按压预算。Windows 不是硬实时系统，因此实机验收仍需记录调度迟到；一旦检测到迟到，程序失败关闭而不是继续使用错误的逻辑累计。该修复不引入视觉位置闭环，也不改变一期随机游走规则。
