# Broker 按键租约截止设计

日期：2026-08-20

## 问题

当前 Host 使用 `Task.Delay(holdMs)` 后主动释放按键，Broker 只在 `250ms` watchdog 中检查租约。系统负载升高时，配置为 `25-49ms` 的方向键可能晚于计划上限释放，而移动规划器仍按抽样值累计偏移。窄平台上，逻辑偏移与游戏实际位移会因此失配。

## 决策

第一次实现把攻击键和方向键放进同一种严格租约，并把 Host 稍晚到达的 `KeyUp` 当成 `KEY_LEASE_DEADLINE_MISSED`。实机日志证明这会让攻击在第一轮后停止，因此该实现已回退。

当前实现只为 `MoveLeft/MoveRight` 注册独立物理截止。截止到达时 Broker 立即发送方向键 `key-up` 并移除活动键；Host 随后的 `KeyUp` 返回幂等 `KEY_ALREADY_UP`，不得停止会话。攻击键不进入这个短移动截止，仍由 Host 正常收尾；断联、心跳超时和安全门异常继续由 Broker watchdog 兜底释放。

移动规划使用当前净偏移 `relativeOffsetMs` 约束 `[-maxLateralMoveMs,+maxLateralMoveMs]`。相反方向会恢复安全空间，不设置会让连续攻击最终必然停止的整个会话总行程上限。

## 调度器

生产调度器维护活动 action 到 deadline/generation/callback 的映射，并由单一后台线程等待最早截止。线程使用单调毫秒时钟、提前唤醒加短自旋抵达截止点，并设置高线程优先级。新增、取消或替换租约时唤醒线程重新计算最早截止。回调在调度器锁外执行，避免与 Broker 会话锁形成死锁。

测试使用可控的手动调度器，不依赖真实时间。测试必须证明：成功方向键 KeyDown 立即登记截止；触发截止会释放且不解除目标；旧 generation 不能释放新租约；显式 KeyUp/ReleaseAll 会取消任务；截止后的 Host KeyUp 幂等成功；攻击键不登记短移动截止。

## 状态与异常

Broker 会话为每个活动 action 保存租约和 generation。显式 KeyUp 与截止回调都在同一会话锁内串行化。先取得锁的一方完成释放，另一方只能读取幂等结果，不能重复发送物理 KeyUp。

`250ms` watchdog 继续负责 heartbeat 超时、窗口身份和失焦兜底，但不再作为动作租约的正常执行路径。任何安全回收都会取消所有截止任务并清除已完成结果。

## 边界

该修复让方向键不再依赖 Host 的软延迟释放，并要求移动规划器始终限制净偏移边界。自动截止不产生会话错误，也不影响攻击键。Windows 不是硬实时系统，仍需用实机日志观测调度迟到；该修复不引入视觉位置闭环，也不改变一期随机移动顺序。
