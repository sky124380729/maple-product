# 视觉平台与人物模板独立配置设计

## 目标

人物发型、装备和外观未变化时，只采集一次人物模板。用户更换地图或台阶后只重新框选黄色平台，不再重复框选人物和等待动作采集。原生预览展示已采集人物模板，外观变化时由用户主动更新。

## 方案

继续使用现有 `VisualStationaryProfile` 和单文件原子保存，避免配置迁移和识别链路改动；只拆分编辑生命周期。

- 首次无人物模板：配置平台后继续框选人物并采集动作。
- 已有 schema 2 人物模板且视口一致：配置平台后保存新平台，人物源框、模板像素、匹配器版本和采集时间保持不变。
- 更新人物模板：沿用当前平台，只框选人物并执行现有 3 秒准备和约 6 秒采集，成功后原子替换模板库。
- 旧 schema 1 名字模板：下次配置平台后完成一次人物采集，升级为人物外观模板。
- 视口尺寸或 DPI 投影变化：现有模板不能静默复用，继续要求重新配置。

## 原生预览

顶部操作收敛为“配置平台”“更新人物模板”“清除视觉配置”。已保存模板在游戏画面外显示为最多 8 张真实缩略图，并显示数量和采集时间。没有模板时缩略图行折叠，不显示空卡片。游戏画面内仍只有有颜色语义的矩形和轻透明填充，不增加文字。

缩略图直接从本机 profile 的 BGRA 像素生成 WPF 位图，不经 React bridge。主窗口入口改称“配置平台安全区”，现有清除命令仍删除平台和人物模板，并保留运行期间不可修改的安全门。

## 状态与异常

- 平台或人物编辑开始前保留当前完整配置，只有新配置校验和磁盘保存都成功后才替换内存观察会话。
- Esc、预览关闭、实时帧不足、校准失败、视口变化或写盘失败均恢复旧配置。
- 更新期间攻击或自动寻路不能启动；攻击或寻路运行期间不能配置、更新或清除。
- 平台复用不会在线修改人物模板，也不会改变识别阈值、随机移动、视觉安全门或持续攻击回退。

## 验证

- 单元测试证明平台替换完整复用人物模板与采集时间，并拒绝无人物模板或视口不一致的复用。
- 原生 WindowsHost 构建证明模板缩略图和两个独立入口可编译。
- 现有人物识别、视觉控制器、普通持续攻击和前端测试全部保持通过。
