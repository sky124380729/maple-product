# 定点移动时间闭环设计

日期：2026-08-22

## 目标

在没有视觉位置反馈的前提下，以 Broker 实际发出的方向键 `keybd_event` 按下和释放时间差作为唯一位移依据，把会话净偏移限制在用户配置的每侧最大偏移内。左按 40ms、右按 30ms 后的净偏移为向左 10ms；相反方向移动会恢复对应安全空间。

本设计控制的是程序输入时间形成的逻辑位移。游戏速度和平台物理边缘无法在无视觉条件下直接测量，用户配置的最大偏移必须取经过实机验证的保守值。

## 根因

当前 Host 在 Broker 确认 `KeyDown` 后执行 `Task.Delay(holdMs)`，再通过命名管道请求 `KeyUp`。线程调度和管道传输会使真实释放晚于计划值，而移动规划器仍按抽样值更新 offset。Broker 的 `250ms` watchdog 只适合 heartbeat 和异常兜底，不能约束 30-50ms 的移动短按。协议和日志也没有携带真实按压时长，因此误差会跨周期累积且不可见。

## 决策

1. 净偏移继续使用有符号时间差，不采用左右总行程预算。
2. 仅 `MoveLeft/MoveRight` 使用 Broker 内部的独立截止调度；攻击键继续由 Host 正常收尾。
3. Broker 在物理 `keybd_event` Down 成功后记录单调时间，在自动截止或显式 Up 成功后记录释放时间，并把 `actualHoldMs` 与 `releaseLatenessMs` 返回给 Host。
4. 自动截止后的 Host `KeyUp` 是幂等成功，不得因此停止会话。释放失败仍是安全停止条件。
5. 控制器逐段规划移动：第一段根据当前真实 offset 抽样，完成并提交真实时长后，才抽样间隔和第二段；第二段必须使用更新后的 offset 重新计算预算。
6. 每次抽样从剩余空间中预留固定的 `20ms` Broker 释放安全余量。剩余空间不足最小按压与 `20ms` 之和时，当前会话安全停止。
7. 单次真实释放迟到超过 `10ms` 时保留完整诊断，但只要按真实时长更新后的 offset 仍在配置边界内就继续；真实 offset 越界才停止并 `ReleaseAll`。

## Broker 调度

生产调度器只管理方向键租约，使用单一后台线程、单调时钟和 generation 防止旧截止释放新租约。对不超过 `100ms` 的短移动租约，调度线程登记后持续检查单调截止点，不执行可能过睡的阻塞等待；较长导航租约可等待到剩余 `100ms` 后进入持续检查。回调在调度器锁外执行；Broker 会话自己的锁负责串行化自动截止、显式 `KeyUp` 和 `ReleaseAll`。

`250ms` watchdog 继续负责 heartbeat、窗口身份、失焦和最终兜底，不参与正常移动短按截止。

## 状态与协议

Broker 响应增加可选字段：

- `actualHoldMs`：成功物理 Down 调用返回后到成功物理 Up 调用返回后的单调时长；
- `releaseLatenessMs`：`max(0, actualHoldMs - requestedLeaseMs)`。

Host 的移动动作结果必须携带这两个字段。规划器只接受成功动作的 `actualHoldMs`，不能再用请求的 lease 更新 offset。日志必须同时记录请求时长、真实时长、迟到量和更新后的 offset。

## 边界与异常

- 真实按压时长必须为正；缺失、负数或不可能的大值视为 Broker 协议错误并停止。
- 第一方向预算不足时不交换方向，保持最终朝向约束。
- 第二方向预算不足、释放失败、真实 offset 越界或协议数据非法时停止并释放全部按键；迟到超出 `10ms` 但 offset 未越界时继续。
- 新会话 offset 从 0 开始；攻击周期、移动周期和休息均不清零。
- `ReleaseAll/Close` 取消所有移动截止并保持幂等。

## 测试

- Broker 测试证明移动 Down 会登记独立截止，截止会物理释放但不解除目标，旧 generation 不影响新动作。
- Broker 测试证明显式 Up 和自动 Up 都返回真实时长与迟到量，自动 Up 后的 Host Up 幂等成功。
- 控制器测试使用“请求 40ms、实际 46ms”等数据，证明 offset 按 46ms 更新，第二段预算基于真实值。
- 边界测试证明每段都预留 `20ms` 释放安全余量，预算不足和真实 offset 越界都会停止并 `ReleaseAll`。
- 控制器测试证明请求 `35ms`、实际 `46ms` 的 `11ms` 偶发迟到在真实 offset 未越界时不会停止。
- 长周期测试证明只要每次迟到不超过 `20ms`，真实时长形成的净 offset 始终位于配置边界内。
