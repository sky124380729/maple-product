# 视觉回正朝向恢复设计

## 问题

视觉位置超过中心带时，控制器只执行一段向内移动并开始下一轮攻击。若该方向与会话初始朝向相反，人物会以错误朝向攻击一轮或多轮，直到后续完整双向移动碰巧恢复。

## 证据

2026-08-25 最新会话日志中，初始朝右的完整视觉移动为 `MoveLeft -> MoveRight`。第 96、97、101 和 103 轮在正像素偏移超过保护带后只出现 `MoveLeft`，随后直接出现下一轮 `AttackHolding`。控制器的中心带外分支在一次 `TryMoveAsync` 后直接返回，未进入既有 `RestoreInitialFacingAsync`。

## 行为

- 向内修正方向等于初始朝向时，一段随机修正后已经满足朝向要求。
- 向内修正方向与初始朝向相反且实际执行成功时，进入 `FacingRestorePending`。
- 恢复期间每次使用最新可信观察重新计算向内方向。仍在中心带外时继续独立随机向内修正，不发送危险外移。
- 回到中心带后，安全执行一次独立随机时长的初始朝向移动，发布 `VISUAL_FACING_RESTORED`，然后才允许下一轮攻击。
- 每段继续使用既有视觉授权、撤销令牌、稳定等待、反馈帧和随机范围。不得固定总时长或放宽平台安全门。
- 连续视觉不可用达到 15 秒时沿用既有持续攻击回退规则，避免无限阻塞攻击。

## 不变边界

- 不修改普通持续攻击控制器、随机数来源、配置 schema、识别阈值或 Broker 输入协议。
- 不允许在视觉保护带中仅为转向而向平台外侧点击。
- 视觉覆盖层精简是同一版本中的独立 UI 修复，不影响本状态机行为。

## 测试

- 初始朝右、连续两个正偏移超中心带的场景必须产生 `Left -> Left -> Right`，且只在最后一个 Right 后允许下一轮攻击。
- 初始朝向与向内方向相同时仍只需一段随机修正。
- 既有第二段缺失恢复、视觉失信回退、安全门和随机移动测试保持通过。
