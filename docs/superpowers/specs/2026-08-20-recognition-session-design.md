# 识别会话基础设计

## 目标

建立一条可复用的 Windows 游戏画面采集与识别会话，供实时预览、持续攻击和后续自动寻路共同消费。识别开关打开后，持续攻击也持续提供角色与 HUD 状态，至少包括 HP、MP、EXP；未来的喝药策略只消费识别快照，不直接读取窗口像素或操作输入。

本阶段只建设会话、数据契约、生命周期和诊断能力，不启用自动寻路攻击，也不把识别结果直接转换成按键。

## 方案选择

### 共享会话（采用）

由一个 `RecognitionSession` 管理窗口绑定、帧采集、识别流水线和最新快照。预览和运行模式分别持有会话租约；至少有一个租约时流水线运行，最后一个租约释放后停止并释放采集资源。这样不会为预览、持续攻击和自动寻路重复创建采集线程，也能保证模式切换时 HP/MP 状态连续。

### 模式内独立会话（不采用）

每个模式自己创建采集和识别对象，初期代码较少，但会重复占用 GPU/CPU，并在预览切换或模式切换时丢失状态。

### 独立识别进程（暂不采用）

隔离性和崩溃恢复较好，但当前阶段需要额外的 IPC、窗口身份传递和部署维护，不符合一期后的最小增量目标。

## 生命周期

1. 用户打开识别开关并打开实时预览时，主机发现唯一游戏窗口，创建预览租约并启动共享会话。
2. 用户打开识别开关并开始持续攻击时，运行会话创建运行租约；即使预览关闭，角色/HUD 识别仍持续运行。
3. 未来自动寻路开始时，自动寻路创建导航租约；导航模式必须使用同一会话，不能另起采集管线。
4. 最后一个租约释放后，会话取消采集、等待在途帧和识别任务退出，然后释放窗口捕获资源。
5. 运行模式停止、窗口关闭或目标身份失效时，先撤销导航/运行租约，再执行现有输入释放和 Broker 关闭流程。识别停止不得绕过按键释放安全链路。

窗口绑定使用现有 `WindowLocator` 和 `WindowIdentity`。预览空闲时解析唯一目标窗口；运行时绑定启动时记录的 HWND、PID、路径和启动时间，后续帧必须持续通过身份检查。

## 组件与边界

### `IFrameCaptureSource`

沿用现有 WGC 捕获抽象，输出带宽度、高度、步长、像素、采集时间和单调序号的 `CapturedFrame`。捕获实现只负责拿到帧，不包含模型、输入或 UI 逻辑。

### `RecognitionSession`

负责租约计数、捕获循环、背压、取消和故障状态。只保留最新帧，旧帧在识别繁忙时丢弃，避免延迟无限累积。每个识别结果携带源帧序号和采集时间。

### 识别提供者

通过可替换接口拆分动态和静态识别：

- `IDynamicRecognitionProvider`：角色、自身位置、怪物、掉落物、其他玩家。
- `IHudRecognitionProvider`：角色名称、等级、职业、HP、MP、EXP 及对应置信度。
- `IMapObservationStore`：地图指纹、关键帧、平台线、梯子和边界标注。

第一版允许使用诊断提供者返回“未识别”状态，接口和快照格式必须稳定，不能在 `MainWindow` 中硬编码 OpenCV/YOLO/OCR 调用。真实模型接入后只替换提供者实现。

## 数据契约

每次发布 `RecognitionSnapshot`，至少包含：

- `sessionId`、目标 `WindowIdentity`、源帧序号、采集时间、结果发布时间和帧龄。
- `self`：屏幕坐标/地图坐标（可为空）、朝向（可为空）、置信度。
- `monsters`、`drops`、`otherPlayers`：位置、类别（可为空）、置信度和观察时间。
- `hud`：角色名、等级、职业、HP 当前值/最大值/百分比、MP 当前值/最大值/百分比、EXP 百分比；字段可为空并带置信度。
- `health`：`Running`、`Stale`、`Faulted`、`TargetLost`，以及稳定错误码和诊断文本。

快照按序发布，消费者只能读取不可变副本。超过新鲜度阈值的快照标记为 `Stale`，不得用于喝药或导航决策；丢帧、模型异常和 OCR 失败必须可观测。

其他玩家永远不是攻击目标。识别结果在进入未来导航策略前还要经过窗口身份、安全门和地图一致性检查。

## UI 与运行模式

- 识别开关是独立配置项，默认关闭；保存配置不启动会话。
- 实时预览打开且识别关闭时，可以继续显示原始帧和采集诊断，但不运行识别提供者。
- 识别打开后，预览面板显示最近快照的帧龄、识别状态、HP/MP/EXP 和各类目标数量；主运行状态不承载逐帧图像。
- 预览窗口必须在原始画面上显示识别结果：角色/怪物/掉落物/其他玩家的标记或边界框，以及 HP/MP/EXP、置信度和帧龄诊断；模型尚未提供结果时显示明确的“未识别”状态，不得伪造目标。
- 持续攻击只读取快照用于未来喝药策略；本阶段不因识别结果改变攻击节奏，也不发送额外按键。
- 识别故障只停止识别消费者并发布故障状态，不自动恢复焦点、不绕过现有停止流程；持续攻击仍按现有安全策略运行或由控制器按明确错误码停止。

## 地图录制

录制复用同一帧流，保存地图指纹、低频关键帧和人工标注的楼层/平台/梯子/边界。录制不保存可直接回放的按键宏，也不把单张截图当作永久地图。地图数据必须带目标窗口身份、分辨率、缩放和采集时间，加载时先验证指纹和几何一致性。

## 资源与安全

- 采集循环有取消令牌和在途任务等待；关闭窗口时不得遗留 WGC/SharpDX 资源。
- 识别队列采用单生产者、最新帧覆盖策略，设置每帧最大处理时间和结果新鲜度阈值。
- 识别会话不拥有 Broker，也不直接调用 `keybd_event`；输入仍唯一经过 Broker。
- 目标窗口丢失、身份变化、捕获故障或结果过期时，导航/喝药消费者必须 fail-closed。输入释放和 Broker watchdog 继续由现有链路负责。

## 测试与验收

单元测试覆盖：

- 租约并发获取/释放、最后租约停止、重复释放和取消时在途帧排空。
- 最新帧覆盖、序号单调、结果不可变副本和 stale/faulted 状态转换。
- HUD 数值解析边界（空值、百分比、最大值为零、OCR 低置信度）。
- 目标过滤（其他玩家不可成为攻击目标）和窗口身份失效。
- 预览租约、持续攻击租约、导航租约共享同一采集实例。

Windows 验收在真实客户端上确认：识别开关打开后持续攻击期间 HP/MP/EXP 快照持续更新；关闭预览不停止识别；关闭识别后资源释放；切换到未来导航模式不创建第二条采集管线；捕获/识别故障不会留下按键或 Broker 进程。

## 非目标

- 本阶段不实现怪物识别模型、OCR 模型或自动寻路策略本身。
- 本阶段不启用识别攻击模式，不将识别结果直接映射为移动/攻击按键。
- 本阶段不改变一期持续攻击的默认参数、焦点安全门和 Broker 协议。
