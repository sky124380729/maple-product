# 地图包只读加载与观察设计

## 背景

二期需要把地图中的平台、梯子、边界和怪物模板提供给识别与后续导航层。现阶段不启用自动寻路，也不发送任何新的输入动作；本阶段只建立可信、可测试的地图包观察数据源。

## 目标

- 从 `.mapzip` 读取 `manifest.json`、`map.json` 和怪物模板条目。
- 将地图结构转换为稳定的只读 DTO：平台、梯子、平台连线、跳跃/掉落/传送连线、站点和模板元数据。
- 在加载边界拒绝损坏、超限或不安全的归档，错误使用稳定的 `MAP_PACKAGE_INVALID:*` 代码。
- 不依赖辅助目录中的具体地图文件；测试使用内存构造的合成 zip。

## 输入约束

归档必须包含 `manifest.json` 与 `map.json`。manifest 的 `format` 必须为 `madudu_map_package`，`version` 必须为 `1`。路径必须使用 `/`、不能是绝对路径、不能包含 `..`，单个条目不超过 16 MiB，条目总数不超过 512，总解压大小不超过 64 MiB。

`map.json` 中的平台、梯子和连线 ID 必须唯一；坐标、范围和阈值必须为有限数值；所有连线引用的起止平台必须存在。未知字段允许保留向后兼容，未知归档条目忽略但仍受大小限制。

## 输出与边界

`MapPackageSnapshot` 及其子 DTO 全部为不可变记录。快照不暴露可修改集合。模板只返回相对归档路径、文件大小和 SHA-256，不在本阶段加载图像或运行检测。

加载器是纯观察组件：没有窗口句柄、没有 Broker 依赖、没有输入调用，也不自动选择地图。后续识别会话可通过快照匹配平台和模板；自动导航必须另行通过二期验收后才可启用。

## 验收

- 合法合成包能够完整加载并保留平台、梯子、连线、阈值和模板元数据。
- 缺失文件、错误格式/版本、重复 ID、悬空连线、非法路径和超限归档均返回稳定错误，不抛出未处理的 JSON/压缩异常。
- 读取后的集合不可被调用方修改。
- 单元测试覆盖上述边界；现有一期和识别测试保持通过。
