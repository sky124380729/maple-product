# 持续攻击换向释放结算设计

## 问题证据

2026-08-24 会话 `6b5e21c5-5b90-4dbf-94e2-b2d368621370` 以 `manual:Right` 启动，共完成 202 轮。日志记录左、右各 202 次物理按键，左侧实际累计 `9541ms`，右侧实际累计 `9588ms`，Host 最终计算 `+47ms`，但实机人物长期向左偏移。输入没有漏发，按压时间也没有向左倾斜。

普通持续攻击每轮固定执行初始朝向反方向后再恢复初始朝向。第一段在攻击释放固定 `100ms` 后执行，第二段只在第一段释放后的配置随机间隔后执行。当前实机配置为 `40–70ms`，因此两段进入游戏输入帧的前置结算条件不一致；仅用物理按压毫秒作为位移等价量无法表示这种阶段响应差异。

## 设计

只修改普通 `StationarySessionController`：

- 第一方向成功释放并提交真实时长后，第二方向前增加固定 `100ms` 方向释放结算缓冲。
- 现有 `StationaryMovementPlanner.SampleGapMs` 继续独立抽取配置随机间隔。
- 权威 `MoveGap` 阶段时长发布为 `100ms + sampledMoveGapMs`。
- 两段方向顺序、随机按压时长、边界规划、回中概率、最终攻击朝向、攻击与休息随机逻辑全部保持不变。
- 视觉增强控制器和 Broker 释放时序不修改。

当前配置随机间隔为 `40–70ms` 时，第二方向开始前的总无键时间为随机 `140–170ms`，不是固定 `100ms`。

## 异常与测试

等待继续使用现有分片安全检查；缓冲期间失焦或取消沿用当前停止和 `ReleaseAll` 路径。控制器测试固定抽中 `47ms`，断言发布的 `MoveGap` 为 `147ms`，同时保留完整 `Attack -> Left -> Right` 顺序断言。
