# 地图包驱动的单地图自动寻路设计

日期：2026-08-22
状态：已确认，等待实施计划

## 目标

产品从用户选择的目录读取既有 `.mapzip`，由用户在主界面下拉框中选择本次地图。运行时使用所选包的人工小地图区域、平台、梯子和怪物模板完成实时定位、路径规划、闭环移动、全图巡逻和自动攻击。

首张 Windows 实机验收地图是“沼泽地3”，但实现不得包含地图名称、平台数量、坐标或文件路径常量。切换地图只能替换所选 `MapPackageSnapshot`，不得替换导航控制器。

## 已确认范围

- 首版由用户手动选择地图，不自动在多个包之间识别当前地图。
- 当前画面无怪物时，前往最久未访问的平台继续全图巡逻。
- 首版不捡取掉落物、不喝 HP/MP 药、不执行跳跃或下跳。
- 平台间移动只使用左右行走和包内双向梯子；所选地图的梯子子图不连通时拒绝启动。
- 产品只有“完整运行”，不提供只观察、单连接或分阶段运行按钮。
- 实施期间仍必须通过离线、模拟和真实预检；这些不是用户可选运行模式。

## 非目标

- 自动识别当前属于 42 个包中的哪张地图。
- 跨地图、传送门、跳跃、下跳、绳索以外的特殊移动技能。
- 自动补血、补蓝、拾取、回城或死亡恢复。
- 迁移或调用开源程序的 Python EXE、输入实现或不可审查运行逻辑。
- 把 Player 或 OtherPlayer 当作攻击目标。

## 地图目录与选择

`MapCatalog` 只读扫描用户选定目录中的 `.mapzip`。目录通过原生文件夹选择器设置，并保存到独立的导航设置文件；不得硬编码桌面“辅助”路径，也不得把二进制地图包提交到产品仓库。

目录扫描对每个包调用 `MapPackageLoader`。无效包显示稳定错误但不能进入下拉选项。下拉标签使用文件名和包内 `map_name`；二者不一致时显示警告并禁止首版运行，避免加载已发现的错标包。

每次启动导航前重新读取选定文件并计算 SHA-256。会话期间文件内容变化时立即停止，不能在运行中热切换拓扑。

`MapPackageSnapshot` 需要增加以下只读字段：

- `minimap_rect`：`x, y, width, height`，全部为正整数且必须位于捕获帧内。
- `minimap_rect_source`：诊断字段。
- 包文件哈希和源路径由 `MapCatalogEntry` 保存，不进入地图 JSON 合同。

## 运行组件

### MapCatalog

负责目录扫描、包加载、名称一致性、重复地图名和文件变化校验。它不参与实时帧处理或输入。

### MapSignatureMatcher

把包内平台和梯子栅格化为期望小地图结构，并与 `minimap_rect` 内的实时平台/梯子结构比较。预检要求连续 5 个新帧满足：

- 捕获尺寸允许完整裁剪 `minimap_rect`；否则 `MAP_VIEWPORT_MISMATCH`。
- 平台覆盖率至少 70%。
- 匹配几何的归一化坐标距离不超过包内 `match_threshold`。
- 角色标记能够稳定检测。

这 5 帧属于有界预检握手：Host 必须发布 `MAP_VALIDATION_PENDING` 进度并等待最多 3 秒，期间不得发送任何输入；只有握手成功后才进入运行态。预检超时返回 `OBSERVATION_STALE`，确定失配返回对应的地图或视口错误，不能把尚未完成的握手误判为运行态帧过期。

预检未解锁时，只要地图结构仍匹配，单帧角色黄点缺失必须重置连续帧计数并继续发布 `MAP_VALIDATION_PENDING`，不得直接发布 `SELF_NOT_LOCALIZED`。只有地图结构本身失配才保留原始地图错误；黄点持续不能稳定确认时由 3 秒预检总超时统一停止。

Windows OCR 可用时，预检还必须读取小地图标题并与包内 `name` 连续确认 2 次。比较时忽略空白和标点，允许非数字文字存在单字 OCR 偏差，但双方出现的数字序列必须完全一致；因此 `沼泽坦3` 可以确认 `沼泽地3`，`沼泽坦2` 必须拒绝为 `MAP_NAME_MISMATCH`。标题未完成确认时保持 `MAP_VALIDATION_PENDING` 且不得发送输入。运行中继续低频复核标题，确定变化时安全停止。

开源包的地图几何以 `1366×768` 客户端逻辑像素为基准；但 `madudu_map_package v1 / app_version 1.0.0` 的 `minimap_rect.y` 来自含 32px 标题栏的 `1366×800` 外窗截图。Host 加载该包版本时必须保留 `minimapReferenceTopInset=32`，投影到已裁剪客户区的 WGC 帧前扣除该偏移，不得按地图名称或某张地图坐标特判。Windows Graphics Capture 可能因系统 DPI 返回等比例放大的物理像素帧；Host 必须先验证宽高缩放一致，再把校正后的 `minimap_rect` 和地图采样点投影到物理帧。定位结果必须反投影回包内逻辑坐标后再交给路径规划，不允许把 DPI 比例写入地图包或控制器。

运行中单帧失败不会立即停止；连续 3 个新帧失配或最后有效匹配超过 500ms 时返回 `MAP_MISMATCH`。

### MinimapLocalizer

只在已验证的包内 ROI 中检测角色黄点；客户端黄点中心位于人物脚底上方约 7 个逻辑像素，因此 Host 必须把中心转换为脚底锚点，再映射到包内小地图像素坐标。正常站立时，只有同时满足以下条件才发布当前平台：

- 正常定位时 X 位于平台范围外扩 3 像素内；若角色落在包未建模的窄落脚点，允许在同高度上把 X 距离不超过 12 像素的唯一近邻平台作为恢复平台。存在两个候选时不得猜测。
- Y 与平台 Y 的距离不超过 5 像素。
- 候选平台唯一。

角色位于梯子中间时允许平台暂时为空，但必须处于一个正在执行且未超时的 `TraverseConnector` 动作中。启动首次定位时若黄点位于包未登记的窄落脚点，控制器只允许向同高度、水平范围距离不超过 12 像素的唯一最近平台执行 80ms 左右短脉冲；最近距离并列、没有近邻平台或距离超界时不得猜测。只有黄点 X/Y 已落在包内梯子范围，或正在延续尚未超时的已确认梯子动作时，才允许发送 100ms `Down` 短脉冲。单独 `Down` 不得被当成穿平台或下跳，首版不发送 `Down+Jump`。恢复与普通移动共用无位移检测和安全门；平台连续 3 帧无法恢复时返回 `SELF_NOT_LOCALIZED`。

### NavigationGraph

平台是节点，梯子是双向边。首版忽略 `platform_links`、`jump_links`、`drop_links`、`portal_links` 和 `teleport_links`。启动前验证：

- 每条梯子引用两个存在的平台。
- 从任一平台通过梯子能够到达所有平台。
- 梯子 X 位于两个关联平台可接近的范围内。

不满足时返回 `MAP_GRAPH_UNSUPPORTED`。A* 边成本由到梯子入口的水平距离和垂直距离组成，启发函数只使用平台间最小垂直距离，保证不会高估。

### PatrolTargetSelector

保存每个平台最近一次确认到达的单调时间。没有可攻击怪物时选择最久未访问的平台；并列时选择当前 A* 成本最低者。当前平台不能连续成为巡逻目标。

### MonsterTargeting

包内怪物模板是首版唯一的攻击授权来源。候选必须在最近 3 个不同捕获帧中至少 2 帧达到包内 `monster_color_corr_threshold`，并且不能位于 HUD 或小地图区域。现有通用怪物识别只用于合并重叠框和提高诊断置信度，不能单独触发攻击。

候选框与 Player、OtherPlayer 或 Self 重叠时直接排除；这些类别永远不能成为攻击目标。首版只处理与角色脚底高度差不超过包内 `attack_range_height_pixels` 的同平台目标。

同平台最近怪物进入 `attack_range_pixels` 时发送短攻击动作；距离更远时只在当前平台安全内边界内短距离接近。怪物消失或目标变化不是异常，控制器取消目标并重新观察。

### NavigationController

控制器依赖不可变地图快照、实时定位源、怪物目标源、A*、Broker 动作接口、单调时钟和状态发布器，不依赖 React 或具体视觉实现。

状态为：

1. `Preflight`：地图匹配和角色定位。
2. `Patrolling`：选择最久未访问的平台。
3. `Planning`：生成平台路径。
4. `Walking`：在当前平台内走向怪物或梯子入口。
5. `AligningConnector`：把角色 X 对齐到梯子容差内。
6. `TraversingConnector`：分段按 `Up` 或 `Down`。
7. `VerifyingArrival`：确认到达预期平台。
8. `Combat`：接近并短攻击，之后重新观察。
9. `Stopped`：释放输入并发布稳定原因。

任何时刻只允许一个输入动作在途。观察更新可以取消尚未开始的计划，不能让旧计划与新计划并行发送输入。

每个移动脉冲发出后，控制器必须忽略动作持有期间以及释放后 150ms 内捕获的位置帧；这些帧可用于地图名和安全校验，但不得触发下一个输入，也不得累加无位移次数。`NAVIGATION_STUCK` 仍要求 3 次有效反馈帧均无可测位移。

## 输入动作

生产输入仍唯一使用普通权限 Host、管理员 Broker、命名管道和 `keybd_event`。在现有白名单基础上增加方向动作 `MoveUp` 和 `MoveDown`，使用扩展方向键扫描码；不得引入 SendInput、PostMessage 或 React 按键路径。

默认动作边界：

- 水平移动单次 40-120ms，动作后等待新定位帧。
- 梯子对齐容差 3 个小地图像素。
- 上下梯单次 80-150ms，持续确认 Y 朝预期方向变化。
- 攻击单次 200-400ms，使用现有配置的攻击键，动作后重新识别怪物。
- 同一动作连续 3 次没有可测位置变化时停止。

动作时长由 Host 在边界内决定并发送给 Broker。Broker 记录活动键；断连、心跳超时、目标身份变化或 Host 停止时无条件 `ReleaseAll`。

## 数据流

1. React 提交地图目录、选定包和“开始自动寻路”意图，不提交坐标、路线或按键。
2. Host 停止现有定点会话，加载地图快照并启动绑定窗口的采集/识别。
3. `MapSignatureMatcher` 和 `MinimapLocalizer` 完成 5 帧预检。
4. Host 将游戏窗口置前，连接 Broker，再次校验窗口和最新观察。
5. `NavigationController` 选择怪物目标或巡逻目标，A* 生成平台路径。
6. 控制器只执行路径的下一个短动作，等待新观察确认后再继续。
7. 状态发布器向 React 发送地图、当前平台、目标平台、路径、动作、定位置信度和停止原因。

## 安全停止

下列情况立即取消计划、尝试释放当前键、执行 `ReleaseAll` 并停止：

- `MAP_PACKAGE_INVALID`：包加载或结构校验失败。
- `MAP_PACKAGE_CHANGED`：会话固定的地图包哈希在运行期间发生变化。
- `MAP_NAME_MISMATCH`：文件名与包内名称不一致。
- `MAP_VIEWPORT_MISMATCH`：包内 ROI 不适用于当前捕获尺寸。
- `MAP_MISMATCH`：当前小地图不再匹配所选包。
- `OBSERVATION_STALE`：最新有效观察超过 500ms。
- `NAVIGATION_OBSERVATION_FAILED:*`：捕获、OCR 或模板识别线程发生未预期故障；Host 必须发布稳定错误并释放所有输入。
- `NAVIGATION_OBSERVATION_START_FAILED:*`：原生采集或模板会话未能启动；Host 必须释放已创建的观察资源与 Broker。
- `NAVIGATION_RUNTIME_FAILED:*`：控制器发生未预期故障；Host 必须释放所有输入和运行资源并发布错误。
- `SELF_NOT_LOCALIZED`：非梯子动作期间无法唯一定位平台。
- `NAVIGATION_STUCK`：连续 3 个同类动作的有效反馈帧没有可测位移；按键释放后 150ms 内的帧不计数。
- `CONNECTOR_TIMEOUT`：梯子动作未在期限内到达目标平台。
- 失焦、窗口消失/最小化/身份变化、Broker 失败、用户停止或程序退出。

怪物消失只触发重新规划，不触发系统通知。其他运行故障沿用现有异常日志和一次 Windows 通知。

## 主界面

主界面增加自动寻路模式和地图目录/地图下拉选择。自动寻路状态显示：

- 所选地图和包状态。
- 地图匹配置信度、角色小地图坐标和当前平台 ID。
- 当前目标平台与 A* 平台路径。
- 当前动作：巡逻、移动、梯子对齐、爬梯、战斗或重新规划。
- 稳定停止原因。

自动寻路和定点攻击互斥，同一目标窗口不能同时存在两个 Broker 输入会话。

## 测试与完整运行验收

自动化测试必须覆盖：

- 目录扫描、42 个开源包加载、错标包禁用、哈希变化和恶意归档边界。
- 固定 ROI 地图签名、连续帧门槛、角色定位和平台歧义。
- 沼泽地3的 7 平台/6 梯子图连通性，以及任意平台对之间的 A* 路径。
- 最久未访问平台选择和当前平台排除。
- 水平移动、梯子对齐、上下梯、到达确认、怪物消失重规划。
- 从包未登记连接点启动时，对唯一下方平台执行有界下行恢复；无安全唯一落点时不发送输入。
- 动作后过早帧不重复发键且不累计无位移，只有释放后至少 150ms 的新帧可驱动下一步。
- 观察过期、失焦、地图失配、无位移、梯子超时和取消时的键释放。
- Player/OtherPlayer 永不成为攻击目标。
- React 只发送意图，不能伪造路线或输入动作。

用户侧只有一次完整运行验收：在 1366x768 客户端的沼泽地3选择对应包后启动，程序必须连续完成多平台巡逻、上下梯子、发现同平台怪物后接近并攻击；无怪时继续前往最久未访问平台。停止、失焦或任何安全门失败时不得留下按键。

完整运行验收前仍需通过全量 .NET/React 测试、Windows Release 构建、包加载复核和真实窗口预检。这里的测试不形成产品中的分级运行模式。
