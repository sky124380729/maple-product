# Client Information Architecture Redesign

## Goal

在不改变攻击、识别、地图或输入行为的前提下，把主窗口重组为可快速扫读和操作的紧凑工作台。

## Design Direction

产品是高频操作的 Windows 自动化控制台，不采用营销页、装饰性大卡片或扩大窗口的方式解决拥挤。沿用 Ant Design 与 Segoe UI，视觉变化度 3/10、动效强度 2/10、信息密度 7/10。使用白色工作面、浅灰背景、墨黑正文、青绿色主操作、红色异常和琥珀色警告；圆角不超过 8px，阴影只用于弹窗和浮层。

## Information Architecture

顶部命令栏由品牌、`定点攻击`/`地图管理` 一级页签和页面级操作组成。定点攻击页的第一行是两个同级状态面板：左侧角色状态，右侧运行状态。第二行是配置工作区，基础选择常显，攻击分段和移动参数默认折叠。地图管理页承载录制命令、目录、地图列表、自动寻路控制和寻路状态。

错误不再使用页面顶部全宽 Alert。配置错误、运行错误、停止原因和异常终止记录在运行状态面板内部以紧凑消息条显示。错误文本保持完整，颜色和图标表达级别，不能只依赖颜色。

日志通过顶部图标按钮打开模态窗口。Host 从固定应用数据目录读取 `sessions.jsonl` 的最近 200 条有效记录并发布结构化字段；React 只读展示，不接收可写路径。格式错误的单行跳过，不影响其余日志或攻击会话。

## Interaction Rules

- 保存成功显示短暂成功反馈，失败只显示真实 Host 错误。
- 页签切换本身不提交 Bridge 命令；运行中禁止切换到会与当前会话冲突的页签。
- 折叠只改变可见性，不重置 Form 值。
- 主操作按钮保留文字与图标；次要工具使用图标和 tooltip。
- 默认窗口无需页面滚动即可看到角色状态、运行状态、基础配置和主操作；展开参数使用配置区内部滚动。
- 键盘焦点顺序依次经过页签、工具命令、状态消息、基础配置和折叠标题；日志弹窗打开后焦点受 Modal 管理。

## Compatibility Boundary

保留所有现有配置字段、校验规则、Bridge 命令和消息处理。除新增只读 `loadSessionLog` 命令外，不修改 Host 会话、输入 Broker、随机规划、视觉控制器、地图录制和寻路实现。React 继续不生成随机数、不发送方向动作、不接收逐帧图像。
