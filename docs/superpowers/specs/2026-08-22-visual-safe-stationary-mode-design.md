# 视觉增强定点攻击模式设计

日期：2026-08-22
状态：已确认，已实现，等待 Windows 游戏实机验收

## 目标

在不改变现有“持续攻击”模式任何行为的前提下，新增独立的“视觉增强持续攻击”模式。用户在原生预览中框选固定平台的可站立区域，并紧贴框选自己的角色名字；运行时以名字模板确认本人，以平台固定屏幕坐标作为真实安全边界。随机攻击和随机移动继续保留，累计移动毫秒只作为诊断信息，不再作为该模式的最终安全依据。

该模式解决的核心问题是：左右方向相同的真实按压时长不保证相同的像素位移。斜坡、台阶、角色移动状态和系统调度误差会使纯毫秒模型长期漂移，即使 `relativeOffsetMs` 没有超界，人物仍可能接近或越过平台边缘。

## 模式边界

主界面保留并区分三个定点攻击选项：

1. `持续攻击`：现有纯时间模型。配置、随机规划器、停止规则、日志和输入行为保持不变。
2. `视觉增强持续攻击`：本设计新增。依赖原生捕获、平台安全区和本人名字模板，只在视觉安全门授权后发送左右移动。
3. `识别怪物后攻击`：继续保持 disabled，不因新增视觉安全模式而启用，也不能静默降级为其他模式。

视觉增强模式使用独立的会话控制器和移动安全状态，不向现有 `StationaryMovementPlanner` 增加视觉分支。两种可运行模式只共享攻击节奏抽样、Host 随机数来源、窗口绑定、Broker 协议和 `keybd_event` 输入链路。

## 框选与保存

视觉设置只在独立原生预览窗口完成，React 不接收逐帧像素。

用户依次完成两次框选：

1. 平台区域：框住本次允许人物活动的平台水平范围。框的左右边界是外层硬边界；上下边界用于验证框选合理性和绘制叠加层，不用于自动识别平台贴图。
2. 名字模板：紧贴框住自己的角色名字；存在公会或名字图标时允许一并包含，以增加唯一性。

保存前必须验证：

- 两个矩形均完全位于客户区捕获帧内，宽高达到最小有效尺寸。
- 平台宽度足以容纳两侧保护带和至少一个正常移动区。
- 名字模板不能近似纯色，必须具有足够的亮度或边缘变化。
- 模板和平台配置绑定捕获客户区的宽高与 DPI 投影结果。

框选结果保存到独立的本地视觉配置，不修改原持续攻击配置。相同客户区尺寸下可以复用；尺寸或 DPI 投影变化时视觉模式禁止启动，要求重新框选，不能静默拉伸旧模板。每次启动仍必须重新取得实时名字锁定，保存结果不能直接代表当前人物已经可信。

## 本人识别

本人识别以名字模板为主，不再从所有 `characterCandidate` 中选择最靠近画面中心者。现有 YOLO 人物框只作为空间一致性辅助和预览诊断，不能单独把任何人物升级为本人。

名字匹配器在平台周围的有界搜索区内执行归一化模板匹配，并输出最佳、次佳分数和两者中心。首次锁定只有同时满足以下条件才产生可信候选：

- 最佳分数达到严格阈值。
- 最佳分数与次佳分数之间达到最小差值，避免两个相似候选时猜测。
- 候选横坐标位于平台外层边界附近的合理范围。
- 候选与可用的人物框空间关系合理；人物模型暂时无结果时可以保持候选但不能降低名字阈值。

候选必须在连续 3 个不同的新帧中满足分数和最大跳变约束，才从 `Acquiring` 进入 `Trusted`。进入 `Trusted` 后，以最后可信中心为轨迹锚点，只接受 `12px` 邻域内距离最近的高分候选；搜索区远处的相似峰不撤销当前轨迹，也不能替换本人。邻域内候选等距、候选缺失或不连续会立即撤销本次移动授权；重新连续确认 3 帧后可以恢复。匹配阈值和差值首先采用保守内部默认值，并通过真实截图回放校准；首版不把它们作为普通用户参数暴露。

视觉位置使用名字候选的水平中心。平台只要求横向安全，因此不依赖不稳定的角色脚底框；垂直位置只用于排除明显不在所选平台附近的名字候选。

## 平台安全区

平台在本模式中按固定屏幕坐标处理，不做平台图片匹配或相机位移补偿。该约束成立的前提是定点攻击只产生短距离横移，背景和平台在会话中可视为固定。

外层平台矩形内部再计算左右保护带。保护带初值按捕获宽度等比缩放，并至少覆盖角色半宽、识别抖动余量和一次最大随机移动的保守像素位移。运行中记录每段可信视觉反馈得到的最大单步位移和识别抖动；需要更大保护带时只能向内扩大，不能在会话中自动缩小。扩大后没有剩余安全区时冻结移动并发布稳定故障状态。

人物位置分为：

- `Safe`：位于两个保护带之间，可以执行经过视觉检查的随机候选。
- `GuardLeft` / `GuardRight`：进入左侧或右侧保护带，只允许向平台内部移动。
- `Outside`：超出用户框选的外层平台边界，冻结全部移动，不自动猜测人物仍在原平台。
- `Untrusted`：本人位置缺失、歧义、过期或捕获故障，冻结全部移动。

原生预览绘制外层平台框、左右保护带、内部安全区、当前本人横向标记和状态。主界面只接收结构化状态，不接收平台或模板像素。

## 随机移动规则

视觉模式继续使用加密随机源和现有配置中的移动概率、保持时长范围、段间间隔与稳定等待范围，但由独立视觉规划器生成和授权动作。

- `Safe` 状态下，方向和时长仍随机；候选如果会消耗全部保护余量，则在合法随机区间内重新抽样或缩短上限。
- 越接近保护带，向平台内部的抽样权重越高，但保持时长仍从当前合法范围随机取得。
- `GuardLeft` 只允许随机长度的向右动作；`GuardRight` 只允许随机长度的向左动作。
- 为保持用户指定的初始攻击朝向，正常移动仍优先使用相反方向的成对动作并以初始朝向结束。保护带状态可以省略不安全的向外段，先执行随机向内恢复段并等待新的可信位置；只有重新进入内部安全区且剩余空间足够时，才执行经过安全门授权的随机短段恢复初始朝向。空间不足时保持移动冻结，不能为了恢复朝向再次贴近边界。
- 每一个方向键释放并完成稳定等待后，必须取得新的 `Trusted` 位置，才能发送下一个左右动作。旧帧、动作期间帧和释放前捕获的帧不能授权下一动作。
- 单次视觉位移明显超过当前保护带假设时，立即扩大保护带并冻结后续动作，直到连续新帧重新确认安全位置。

这些限制只裁剪不安全候选，不把正常区域退化为固定左右配对或固定回中时长。诊断日志同时记录随机候选、视觉裁剪原因、实际按压毫秒、动作前后像素位置、保护带和视觉状态。

## 攻击与识别丢失

视觉安全只控制左右移动，不控制攻击键。窗口仍聚焦且 Broker 正常时：

- 名字暂时丢失、可信位置邻域出现等距冲突、捕获暂时失败或预览窗口关闭时，立即冻结左右移动，但当前攻击节奏可以继续。远处相似纹理不影响已有可信轨迹。
- 连续 3 个可信新帧重新锁定本人后，左右移动自动恢复。
- 长时间无法恢复时保持“仅攻击、移动冻结”，不因视觉暂失快速停止整个会话；主界面和预览必须持续显示原因。
- `Outside` 状态不自动执行回中动作，因为人物可能已经离开原平台或候选身份错误。继续攻击但保持移动冻结，等待用户停止和重新框选或手动复位。

失焦、目标窗口身份变化、窗口消失、Broker 故障、用户停止和程序退出仍沿用现有全量释放与会话停止规则，不能因“仅冻结移动”而放宽输入安全。

## 状态与界面

视觉配置状态：

- `NotConfigured`
- `Ready`
- `ViewportMismatch`
- `Invalid`

运行识别状态：

- `Acquiring`
- `TrustedSafe`
- `TrustedGuardLeft`
- `TrustedGuardRight`
- `UntrustedFrozen`
- `OutsideFrozen`

主界面新增“配置视觉安全区”命令和以下只读信息：平台配置状态、名字匹配分数、视觉安全状态、本人相对安全区中心的像素偏移。像素偏移同样使用负数表示左、正数表示右、零表示中心。现有 `relativeOffsetMs` 继续显示并写日志，但在视觉模式中标明为时间模型诊断值，不能覆盖视觉安全状态。

模式切换只改变尚未开始的配置意图；运行中不得从一个模式热切换到另一个模式。未配置或视口不匹配时，视觉模式拒绝启动并打开或聚焦原生配置预览。

## 数据流与组件

1. React 提交视觉模式选择、配置窗口意图和开始/停止意图，不提交像素、坐标、随机数或按键。
2. 原生预览中的 `VisualStationarySetupController` 处理冻结帧和两次框选，调用配置存储保存平台矩形与名字模板。
3. Host 启动视觉会话后绑定目标窗口，加载与当前视口完全匹配的视觉配置。
4. `SelfNameTemplateMatcher` 对新帧产生名字候选；`SelfIdentityStabilizer` 负责分数差值、连续帧和最大跳变门槛。
5. `VisualPlatformSafetyGate` 把可信本人 X 转换为平台安全状态，并维护只增不减的会话保护带。
6. `VisualStationaryMovementPlanner` 生成随机候选并请求安全门授权；控制器只把已授权动作发送给 Broker。
7. 动作结束后 Host 等待稳定期和更新帧，再次经过本人稳定器与平台安全门。
8. Host 向 React 发布结构化视觉状态、像素偏移和诊断，不传输逐帧图像。

以上组件均通过小型不可变合同连接，匹配、稳定、边界判断和随机动作授权可以分别单元测试。现有持续攻击控制器不依赖这些组件。

## 错误与安全边界

- 视觉配置缺失或视口不一致：拒绝启动视觉模式，不影响原持续攻击模式启动。
- 名字模板低纹理或平台过窄：拒绝保存配置。
- 启动锁定超时：保持等待状态且不发送任何输入，用户可以停止或重新框选。
- 运行中位置不可信：停止发送方向键并释放活动方向键；攻击键按既有阶段正常成对释放和抽样。
- 运行中位置越过外层边界：进入 `OutsideFrozen`，不自动恢复移动。
- 捕获线程未预期退出：进入 `UntrustedFrozen` 并记录故障；不能回退到中心最近人物规则。
- 任何模式的失焦、Broker 或窗口安全故障：立即 `ReleaseAll` 并停止会话。

## 测试与验收

自动化测试至少覆盖：

- 视觉配置矩形、模板纹理、视口尺寸和序列化校验。
- 名字模板首次唯一命中、低分拒绝、两个相似候选拒绝、连续 3 帧锁定、锁定后的局部最近候选跟踪、远处相似峰忽略、单帧丢失撤销授权和跳变拒绝。
- 多个人物框存在时，中心最近人物不能替代名字模板成为本人。
- 安全区、左右保护带、外层越界和动态保护带只增不减。
- 安全区域内的方向与时长保持随机分布，边界附近只有合法方向但时长仍随机。
- 每段动作必须等待释放后的新可信帧，旧帧不能触发连续移动。
- 识别暂失和捕获故障只冻结移动，攻击继续；失焦和 Broker 故障仍停止并释放全部输入。
- 视觉模式和原持续攻击模式使用独立控制器；原模式既有测试结果、随机序列边界和停止代码不发生变化。
- React 只能提交模式、配置窗口和会话意图，不能提交视觉位置或方向动作。

Windows 实机验收使用固定画面的短距离平台：框选平台和本人名字后，连续运行足够多轮并安排其他玩家进入画面、短时遮挡名字和技能特效干扰。程序不得把其他玩家升级为本人；可信时人物不得越过外层平台框，失去可信位置时不得继续横移，恢复连续可信帧后可以继续随机移动。验收记录需要包含预览截图、结构化日志、最终像素范围、毫秒偏移范围和发布包哈希。

## 非目标

- 不自动分割任意平台贴图或检测真实悬崖轮廓。
- 不补偿大范围相机滚动；发生视口尺寸变化时要求重新框选。
- 不使用视觉模式启用怪物识别攻击或自动寻路。
- 不训练新的本人/其他玩家分类模型。
- 不修改原持续攻击模式的规划、停止或回中规则。
