# 视觉跟踪锚点与持续回中设计

## 实机证据

会话 `4be98bc5-c7e8-4f98-a454-22bf2ff7b260` 在 `22:39:09` 至 `22:39:19` 之间没有任何左右输入，视觉偏移却从 `-32px` 变为 `-118px`。配置平台宽 `234px`、中心 `1054px`，因此 `-118px` 被判为刚好越过左外框。匹配分数仍为 `0.727`，身份保持可信，控制器进入 `VISUAL_OUTSIDE_FROZEN`，既不会回中也不会触发连续失信回退。

根因是人物外观搜索锚点在每个可信帧上更新。攻击动画期间的低分局部候选可以每帧移动不超过 `12px`，但经过多帧累计后仍能把锚点带离本人；平台安全门随后把错误中心当成真实位置。

## 设计

1. `VisualStationaryObservationSession` 的人物搜索锚点默认锁定。控制器取得方向授权后显式打开动作跟踪窗口，覆盖真实方向保持、释放、稳定等待和动作后可信反馈；窗口关闭后锚点冻结在最后可信中心。攻击、休息和普通捕获期间的候选仍可更新分数与可信状态，但不能累计推进搜索锚点。
2. 平台中心带为 `abs(visualOffsetPx) <= guardWidthPx`。中心带内保留原随机双向动作；可信位置超出中心带但仍在平台外框内时，控制器只执行一次随机时长的向内修正并立即进入下一轮攻击，不执行抵消方向，也不恢复旧朝向。
3. `Outside` 或不可信观察仍不能直接授权视觉移动。连续视觉不可用达到 `15s` 后，在同一个会话内切换到普通 `StationaryMovementPlanner`，按真实累计毫秒值的方向继续随机双向移动，不要求 `px/ms` 校准；累计值越过配置边界时压到同符号边界继续，不能停止攻击。普通回退动作周期保持锚点跟踪窗口开启，以便重新连续 3 帧可信后恢复视觉。观察陈旧或预览/捕获不可用也进入该计时；schema/视口结构错误在启动前拒绝。
4. `FacingRestorePending` 遇到连续视觉不可用也受同一 `15s` 总上限约束。达到上限后结束朝向等待，并从下一轮继续随机攻击和普通持续攻击移动。
5. 视觉中心带双向动作和普通持续攻击回退双向动作的第二方向前均使用固定 `100ms` 释放结算加配置的独立随机间隔。随机攻击、随机方向保持、随机间隔、随机稳定和随机休息全部保留。
6. 人物外观获取、已有轨迹跟踪及短暂失信后的恢复阈值统一为 `0.70`。重新连续 3 帧可信后，从下一完整移动周期退出普通回退并切回视觉平台保护。

## 边界与异常

- 跟踪窗口必须以 `try/finally` 关闭；方向键失败、授权撤销、取消或异常不能让锚点长期处于可漂移状态。
- 主动回中只依赖新鲜可信观察，`Outside`、`Untrusted`、陈旧帧和 fatal 状态均不盲走。
- 普通 `StationarySessionController` 不修改。
- 失焦、窗口身份、Broker 和释放故障继续立即停止并 `ReleaseAll`。

## 测试

- 连续无方向输入帧中的局部候选逐步移动时，搜索锚点不累计漂移。
- 显式动作跟踪窗口内，锚点允许跟随可信人物移动，关闭后再次锁定。
- 可信左/右中心带外状态只发送一次随机向内方向键并继续下一轮攻击。
- 无校准样本时，连续视觉不可用达到 `15s` 后仍执行普通持续攻击随机移动。
- `FacingRestorePending` 连续视觉不可用达到 `15s` 后不再无限阻塞攻击。
- 重新连续 3 帧可信后，下一完整周期切回视觉保护。
- 获取和跟踪阈值均断言为 `0.70`。
- 视觉双向与预测回退间隔均断言为 `100ms + sampledGapMs`。
