# 视觉增强模式朝向恢复门设计

## 问题

视觉增强模式按“初始朝向的反方向 -> 初始朝向”执行一轮左右移动。当前实现允许第一段成功后，第二段因名字不可信、保护带或授权竞态而跳过，并立即进入下一轮攻击。方向键本身会改变角色朝向，因此初始朝向为右时，成功左移但未右移会导致下一轮持续向左攻击。

2026-08-22 实机日志 `1becbf2c-dd49-4b92-8bdb-a3f77941d7db` 证明了该路径：`MoveLeft` Down/Up 成功，第二段由 `VISUAL_AUTHORIZATION_RETRY_TIMEOUT` 跳过，随后直接发布下一轮 `AttackHolding`。

## 行为不变量

1. 只有朝向已确认恢复为启动时的 `initialFacing`，控制器才可发送下一次攻击键 Down。
2. 第一段反向方向键 Down 成功后，本轮进入 `FacingRestorePending`；即使视觉授权在保持期间撤销，仍必须恢复朝向。
3. 只有初始朝向方向键 Down 和 Up 均成功后，才清除 `FacingRestorePending`。
4. `FacingRestorePending` 期间不得进入下一轮攻击、休息或重新抽样攻击时长。
5. 视觉不可信、方向被保护带拒绝或人物位于外框外时，不得为恢复朝向绕过视觉安全门。

## 状态与流程

控制器增加会话内状态 `FacingReady` / `FacingRestorePending`，不写入持久化配置。

每轮流程：

1. 在 `FacingReady` 状态下按现有随机攻击节奏执行攻击。
2. 第一段反向移动没有实际发送方向键时，保持 `FacingReady`，第二段继续按现有视觉规则尝试。
3. 第一段方向键 Down 成功并完成 Up 后，切换为 `FacingRestorePending`。
4. 第二段向 `initialFacing` 移动成功后，清除待恢复状态，完成稳定等待并进入后续流程。
5. 第二段未执行时，停留在恢复循环。控制器以最多 `750ms` 的分段等待获取序列更新的可信观察；每次收到新观察后重新检查保护带、外框、窗口与 Broker 安全门，并重新随机抽样合法保持时长。
6. 恢复循环没有总超时。视觉持续不可信时会话保持运行但攻击暂停；用户停止、失焦、窗口身份变化、Broker 故障或释放故障仍按现有规则立即停止并 `ReleaseAll`。

恢复循环是条件等待，不重复发送方向键，不固定保持时长，也不为完成恢复而临时绕过下述名字分数、次峰差值或连续帧门槛。

## 名字跟踪置信度迟滞

首次锁定本人以及可信轨迹完全丢失后的重新锁定继续使用 `0.90` 最低分、`0.06` 最佳/次佳差值和连续 3 个新帧约束，不降低陌生候选成为本人的门槛。

本人轨迹已建立后，只有候选中心仍位于上一接受位置水平和垂直各 `12px` 邻域内时，持续跟踪最低分使用 `0.86`。该较低门槛用于容忍贴身宠物和轻微动画遮挡；局部等距歧义、跳出邻域、重复帧或分数低于 `0.86` 时仍立即撤销移动授权。短暂撤权后必须重新连续满足 3 个新帧才能恢复可信，不能因降低跟踪门槛跳过稳定过程。

## 状态发布与日志

- 等待恢复时发布视觉代码 `VISUAL_FACING_RESTORE_PENDING`，保留当前名字分数和安全状态。
- 恢复方向键继续使用 `MoveSecond` 阶段，输入日志仍能直接证明 `MoveRight`/`MoveLeft` Down 和 Up 是否完成。
- 不修改原持续攻击模式的控制器、随机算法和状态序列。

## 测试

1. 第一段成功、第二段首次超时、之后视觉恢复：事件顺序必须为 `Attack -> opposite -> initialFacing -> Attack`，第二次攻击不得早于恢复移动。
2. 第一段成功后视觉持续不可信：取消会话前不得出现第二次攻击或额外方向键。
3. 第一段因视觉安全门未执行：不得错误进入待恢复状态。
4. 恢复等待期间取消、失焦或输入失败：立即停止并释放全部键。
5. 保持既有随机范围、保护带方向限制、外框冻结和视觉反馈序列测试通过。
6. 首次候选分数 `0.89` 时不能锁定；已建立轨迹后的本地候选分数 `0.86` 可以保持/恢复轨迹；相同分数但跳出 `12px` 邻域时不能被接受。

## 非目标

- 不强制在不可信或越界状态下移动。
- 不通过攻击键、跳跃或技能修正朝向。
- 不改变原持续攻击模式。
- 不保证视觉永久丢失时自动恢复；此时保证的是不会朝错误方向继续攻击。
