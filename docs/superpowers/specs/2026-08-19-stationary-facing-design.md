# 定点攻击初始朝向设计

## 目标

一期在不依赖视觉识别的情况下，让每轮受限左右移动结束后恢复到用户启动时指定的人物朝向，并为未来的一次性视觉检测保留稳定接口。

## 交互

用户每次点击“开始运行”时，React 先弹出朝向确认框，只显示两个明确动作：`←` 和 `→`。用户选择后才提交 `startStationary`；关闭或取消弹窗不保存、不启动、不连接 Broker。

朝向是本次会话意图，不属于节奏配置，不写入 `config.json`。因此每次启动都重新确认，避免上次保存值与游戏当前状态不一致。

## 数据与边界

启动桥接消息携带人工选择的 `initialFacing: left | right`。Host 不直接信任字符串，而是通过 `IInitialFacingProvider` 解析并返回 `FacingResolution`：成功时包含 `MovementDirection`、来源标识和可选置信度；失败时包含稳定错误码。

一期实现 `ManualInitialFacingProvider`，只接受明确的 left/right。未来 `VisionInitialFacingProvider` 可以在启动时采集一次目标窗口并返回相同结果。视觉置信度不足、画面过期或人物不可见时必须失败或转回人工确认，不能猜测。控制器、规划器和 Broker 不引用任何视觉类型。

## 移动规则

会话开始时将解析后的方向锁定为 `initialFacing`，运行中配置更新不改变它：

- 初始朝左：每轮 `右 -> 左`。
- 初始朝右：每轮 `左 -> 右`。

两段保持时间仍独立随机，间隔和稳定等待规则不变，累计相对位移仍受 `maxLateralMoveMs` 限制。第一方向预算不足时会话安全停止，不能交换顺序；交换会导致第二段结束后的朝向错误。

位置和朝向分别建模。两段时长不要求相等，也不要求回到相对零点；最终按下的方向决定人物朝向。

## 状态与错误

关闭弹窗时页面保持待机。非法朝向返回 `INITIAL_FACING_INVALID`，解析失败返回来源提供的稳定错误码，且不得启动 Broker 或发送输入。会话启动成功后，日志记录解析后的方向和来源，便于未来区分人工与视觉证据。

## 测试

- React 测试：点击开始先显示方向弹窗；取消不发送命令；选择左右分别发送正确启动意图。
- Core 测试：初始朝左生成 `右 -> 左`，初始朝右生成 `左 -> 右`；两段独立抽样；预算不足不交换顺序。
- Host 测试：人工来源解析 left/right，拒绝缺失和未知值；当前会话锁定朝向，下一次启动可以选择不同方向。
- 回归测试：累计位移边界、动作顺序、失焦释放、Broker 输入和倒计时保持通过。
